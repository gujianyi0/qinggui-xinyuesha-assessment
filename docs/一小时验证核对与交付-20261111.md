## 两处故障的证据与修复状态

1. soak 中断的监督进程栈明确为 `status.tmp -> status.json` 的 `PermissionError(WinError 5)`。此前任意状态写盘失败会冒泡并触发全组停止。源目录已实现唯一临时文件、有限重试和失败不抛异常，并令诊断轮转不冒泡。本轮将这部分尚未进入发布库的修复纳入提交。
2. 修复后的启动尝试在 Kafka `LogCleaner` / `SkimpyOffsetMap` 初始化时出现 `OutOfMemoryError: Java heap space`，启动参数限制 `-Xmx256m`。**该日志直接证明 JVM 堆分配失败；不能由当时约 2.7 GiB 可用物理内存推定系统物理内存是唯一根因。** 下一步应核对 Kafka cleaner 缓冲及堆预算，保留既有数据，恢复服务后重新执行完整 3600 秒。本轮是核对与提交，没有调整 Kafka 运行参数。
