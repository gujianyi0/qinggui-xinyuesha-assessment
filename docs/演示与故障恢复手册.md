# 演示与故障恢复手册

演示与故障注入均在本项目隔离环境进行。以下为操作规格，完成状态以相应运行记录为准。

## 1. 演示前准备

1. 按根README安装依赖、配置本项目环境、执行迁移、启动API与独立Worker。
2. 检查`/health`返回的数据库、模型模式和资料快照。需要真实模型证据时确认`model_mode=live`，模型ID与价格已配置且剩余额度足够。
3. 准备两个测试身份alice和bob，分别登录，确认会话与数据范围。
4. 查看`rulings`当前状态。只有已执行并保存断言的裁定才能标记“引擎已验证”。
5. 当前不演示QQ；相关历史实现已归档，运行配置已清理。

## 2. 一次成功请求

网页新建会话，输入“查询标准诸葛亮的势力、体力和技能”，查看逐步输出、结构化工具记录、引用及版本。继续追问“其中没有手牌时针对哪些牌”，检查上下文。刷新或重启API后重新查询本次会话。

保留：运行号、工具调用、最终回答、引用路径、资料快照、耗时和用量。模型替身与真实模型分别报告。

## 3. 一次失败请求

非法输入演示：空消息或超过输入限制的消息应在开始流前返回明确校验错误，不创建伪成功结果。

工具故障演示：在隔离实例显式启用受控故障注入，运行固定F01。检查用户看到原因和重试提示，工具审计记失败，最终运行状态落库；结束后关闭注入。未启用注入时F01应记blocked，不把普通回答算作失败演示。

## 4. 草稿与重复确认

1. 输入“技能没生效，帮我反馈”，检查缺失的武将、技能、步骤、现象、预期和版本。
2. 在反馈页补充字段，查看当前修订号。确认之前正式反馈列表不增加记录。
3. 点击确认，重复发送相同确认请求，验证返回同一反馈ID。
4. 编辑草稿后尝试旧修订号确认，应提示重新查看；不静默接受旧内容。
5. 本轮使用网页确认，不启用历史QQ入口。

## 5. 两身份隔离

alice创建会话、反馈和任务，记录其ID；bob使用自己的token访问这些ID，应被拒绝或视为不存在。反向再检查一次。重启API后重测。公共游戏资料可共享，私人会话、反馈、运行和任务状态不能跨身份读取。

## 6. 后台故障矩阵

| 故障点 | 操作 | 应观察到的结果 |
| --- | --- | --- |
| 同一请求重复提交 | 重复同一幂等键 | 返回原任务，不产生重复最终记录 |
| Kafka重复投递 | 投递同任务与执行代次 | 业务唯一性与状态校验生效 |
| Outbox已发送未标记 | 在指定故障点终止隔离Worker | 重启可能重复投递，最终业务幂等 |
| 写库后位点提交前 | 使用受控故障点终止Worker | 重启识别已提交结果，正确确认位点 |
| 运行中退出 | 终止本项目Worker实例 | 租约过期后可恢复，不永久处理中 |
| 临时依赖失败 | 暂停依赖后恢复 | 最多3次尝试，记录原因与下次时间 |
| 坏输入 | 提交无效白名单快照 | 最终失败，其他正常任务继续 |
| 取消与完成竞争 | 导入时取消 | 最后发布事务核对取消，终态不回退 |
| 旧Worker迟到回写 | 恢复后提交旧代次结果 | 旧代次不能覆盖新结果 |
| Redis失效 | 过期或停Redis | 公共检索回源，任务仍可由数据库查询 |
| Kafka暂时不可用 | 停Broker后提交任务 | 数据库任务可查，恢复后投递，不丢任务 |
| PostgreSQL不可用 | 暂停数据库 | 请求明确失败，恢复后可重试 |

每次记录故障点、请求/任务号、终止时机、恢复步骤、数据库最终状态和日志。服务操作只针对本项目Compose服务，避免终止原轻归、原游戏或其他工作进程。
