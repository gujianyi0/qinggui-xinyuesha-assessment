P09 校验超时并发与失败提示

核对日期：2026-11-14。代码基线：1.9（7453cd3673b02d52b110b16503d283e97e3dac9a）。

状态：已实现，输入输出及协议故障已有验证。

对应要求（原段要点，转述）

提供输入/输出校验、超时与并发控制，模型失败时明确原因和重试性。

来源：故剑遗学习目标 · 功能要求 · 本段。 对应编号：P09。原段SHA256：3bef1531e9db5be8653e47fc1a72dae173da8bb790985c9a95e49e993b4c8cd5。

这是原文一个段落的对应回答。要点使用转述；原段定位和哈希用于复核边界，不把此处概括当作公司新要求。

回答

校验分三层：请求Schema限制字段、长度、编号和类型；工具与业务层限制权限、快照、条件和状态；最终回答Schema限制正文及引用形状。类型合法不能证明规则答案正确，所以还需要来源核对与真实评测。

本项目如何实现

schemas.py的StrictModel拒绝未知字段，RunInput消息为1–8000字符。Runtime使用异步信号量和有界超时，记录failed/error/retryable；finally释放信号量、结算用量并关闭模型异步客户端。缺密钥、缺单价或预算不足不伪装成功。

库中默认并发2、超时60秒；1.9本机真实部署/回归配置为并发1、超时90秒。它们是并发和等待控制，不是按人/按天问答配额。付费总额仍有200元项目上限。

已有验证与证据

  • 输入和模型失败测试、运行与预算测试。
  • Agno协议测试：超时、供应商错误、空正文、工具失败、用量及关闭连接。
  • v19后端209项记录。
  • V01真实超时和同版本重试。

证据按各自原日期与运行模式解释。本次建立QA文档未新增付费模型评测或故障注入；已有测试通过也不等于公司正式验收通过。

怎样核对或演示

在隔离测试中提交空消息/超长消息，确认流前就校验失败；查看超时运行有失败原因、retryable和结算记录。正文为空时应失败，不能用后附反馈清单掩盖。复现命令可用uv run pytest tests/test_api.py tests/test_runtime.py tests/test_agno_protocol.py -q，本轮仅提供指引。

结论与边界

主服务不打开测试故障注入。普通模型输出的业务正确性不能由Pydantic保证；并发已满时明确失败，不是无限排队承诺。用量未知的中断会按预留保守结算，取消和失败不保证没有费用。
