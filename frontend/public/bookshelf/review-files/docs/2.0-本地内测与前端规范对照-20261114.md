# v2.0 本地内测与前端规范对照

日期：2026-11-14。版本：`2.0.0-local.1`。范围：本地内测。基线：1.13（`92022a0bb20737322b2fb67f684ffd741b5fe9c6`）。

本轮按用户指定的《比特鹰前端开发规范》改造现有 React/Vite 网页。保留浅绿与米白主题、原有业务接口、真实模型服务及账本。没有迁移 Next.js、Tailwind 或包管理器；没有更换模型、修改裁定规则、重新执行32条付费模型评测。QQ与真人试用继续移出范围。

## 入口、运行边界与回退

- v2内测：[http://127.0.0.1:15180/](http://127.0.0.1:15180/)。仅监听本机回环地址。
- 1.13对照：[http://127.0.0.1:15174/](http://127.0.0.1:15174/)。原容器、镜像与启动时间保持不变。
- v2复用已运行的 `127.0.0.1:18081` API；两版看到同一主数据库、会话和费用账本。v2使用独立浏览器登录存储键，不会自动继承15174的登录状态。
- v2中实际发送问题仍调用现有真实模型，费用记入原账本；不是另一套免费的模拟业务。密钥保留本机，不进入浏览器和Git。
- 本轮未上传GitHub、未合并main/dev、未修改公网客户端或Cloudflare入口。已有公网服务继续使用1.13。

在项目根目录运行：

```powershell
.\scripts\start_v2_local.ps1
# 已构建并且只需重新启动容器时：
.\scripts\start_v2_local.ps1 -SkipBuild
# 停止v2，不停止15174、API、Worker或数据库：
.\scripts\stop_v2_local.ps1
```

启动脚本先检查现有API，再使用npm锁文件构建明确的本地模式，启动独立Compose项目 `qinggui-assessment-v2-local`。前提是Node满足项目engines且Docker可用、18081服务已运行；此预览覆盖配置不负责迁移或重建主库。首次会下载既有工程同系列的Nginx镜像。停止后直接使用15174即可对照或回退，无需恢复数据库。

## 测试与问题修复记录

### 导入回执损坏造成按钮无法恢复

触发：浏览器保存的导入回执不是合法JSON，或存储读写失败。旧代码在try/finally之外读取JSON，设置提交中后抛错时无法复位。现将读取、结构校验、幂等键保存与提交包进同一try/finally；损坏回执提示先核对任务，不生成另一任务。测试验证没有POST且按钮恢复；另一测试验证响应丢失后两次提交的幂等键相同。没有清空用户真实任务数据。

### 取消与普通HTTP超时

新增15秒HTTP上界后，取消请求也会带独立的有效超时信号。原测试把“不携带已取消信号”写成“完全没有signal”，现修正为检查新signal未取消，仍核对原request ID及取消标记。真实业务语义未改成重复提交。新增测试验证超时不会自动重试POST，以及调用方取消仍保留AbortError。

### 缓存与身份隔离

新增测试验证后台刷新期间保留旧内容，以及切换身份时不能看到上一身份缓存。测试等待用户可见的新内容，而不是假设Query通知与Promise在同一时刻完成；没有调整缓存规则来迁就断言。

### 原有交互回归

来源按需加载后，引用测试等待正文加载再核对；输入面板测试继续覆盖中文输入、右键、组合输入与焦点；来源测试覆盖正文与按钮分离、阅读时不强制跟随、原始代码与Markdown段落。反馈新测试验证打开核对窗口不提交、Esc返回不提交、最终明确确认只携带展示的草稿修订号并只提交一次。
