Agent、工具调用与执行边界（七）：写入、删除、发送操作的确认边界与执行内容绑定

对应学习目标：写入、删除、发送等操作的确认边界；确认后执行的对象和内容必须与用户看到的一致。

文档性质：独立技术知识手册。范围包括模型工具调用、权限、操作预览、内容一致性、一次性确认、并发安全、外部副作用和可追溯审计。代码示例为不依赖模型 API 的可运行教学实现。

1. 为什么需要确认边界

Agent 可以生成计划、选择工具、填写参数，但其生成的建议与现实世界中的动作并非同一回事：

  • 生成意图：模型提出“更新用户的配置”“删除一条记录”“向某地址发送邮件”。此时是未执行的候选动作。
  • 验证操作：可信后端检查发起人身份、授权范围、工具白名单、参数、资源所有权与业务约束。
  • 生成预览：服务器把最终将执行的对象、内容与影响展示出来。预览应由受信任的、已经过校验并冻结的操作快照生成，而不是让模型另写一段可能不一致的描述。
  • 获得确认：有权限的人对该具体动作表达同意、拒绝或请求修改。若内容变更，应重新生成预览并重新确认。
  • 执行副作用：程序实际对数据库、文件或外部服务做出操作，保留执行日志。

关键原则：模型决定建议什么，程序决定有没有资格做，确认人决定是否批准这一份具体的操作快照，执行器只能执行被批准的内容。

confirm=true 这样的模型参数，不是用户确认；聊天中出现“可以”也不能自动替代当前操作所需的显式批准。确认与会话上下文、操作、对象、参数、审批身份及有效期有关。对于风险低且事先明确定义了授权范围的操作，也可由可信程序按策略自动批准；这仍然是程序授权，不是模型自行扩大权限。

2. 三种操作的共同点和差异

操作 典型副作用 应展示什么 执行后可否撤销 典型风险
WRITE：写入/修改 更改数据库、配置或文件 目标、旧值、新值、变更差异、影响范围 视系统版本与备份而定 覆盖并发修改、错误更新
DELETE：删除 软删除、硬删除或撤销资源 具体对象、数量、名称、是否可恢复、连带影响 软删除通常可恢复，硬删除不一定 错删、批量删除、不可逆损失
SEND：发送 向第三方发送邮件、通知或请求 完整收件人、抄送/密送、标题、正文、附件、发送账户 通常不可收回 误发、泄漏、重复发送

“写入”不仅是数据库 UPDATE；还可能是上传文件、提交反馈、推送代码、更改权限、支付、调用外部 SaaS 写入 API。这些行为的共同点是产生现实副作用。

风险越高、越不可撤销，审批内容越需要明确、可理解，并限制批准的作用范围。一个只写“即将发送通知，请确认”的按钮，无法证明用户批准的是哪个收件人和哪份正文。

3. 正确的执行状态机

text
模型提出操作意图
       ↓
后端校验参数、身份和权限
       ↓
PREPARED：生成不可变候选操作快照
       ↓
向有权限用户展示同一份快照的预览
       ↓
       ├─ REJECTED：拒绝，禁止执行
       ├─ EXPIRED：过期，重新预览
       └─ APPROVED：经确认进入执行路径
                       ↓
          再次校验身份、权限、资源版本与快照
                       ↓
              条件性领取/执行操作
                       ↓
          ├─ APPLIED：本地副作用已提交
          ├─ QUEUED：外部副作用已经可靠入队
          ├─ CONFLICT：对象或版本变化，需重新确认
          └─ FAILED / UNKNOWN：明确失败或结果未知

两个不能混同的概念：

  1. APPROVED 是批准决策，不是操作成功；确认 API 返回 200 也不必然意味着第三方已完成动作。
  2. QUEUED 表示已建立可靠待处理记录，不是 SENT 或 DELIVERED。尤其是邮件、支付、外部工单等，需要等待外部调用结果或回执。

对于纯数据库修改，审批状态和业务修改通常应放在同一事务中完成；对于外部系统，通常需要可靠队列/Outbox 与额外的投递状态。

4. “用户看到的”和“程序执行的”必须是同一份内容

4.1 操作快照的构成

一个实用的待确认对象至少包含：

json
{
  "approval_id": "opaque-approval-id",
  "principal": {
    "user_id": "alice",
    "tenant_id": "org-1"
  },
  "operation": {
    "tool": "document.update",
    "resource_type": "document",
    "resource_id": "doc-42",
    "expected_version": 7,
    "arguments": {
      "new_body": "最终写入的全文"
    }
  },
  "policy_version": "approval-policy-v3",
  "expires_at": "2026-11-11T08:00:00Z",
  "payload_digest": "sha256:...",
  "state": "PENDING"
}

以上为示意结构，其中时间和标识仅为示例。approval_id 应使用不可猜测标识，但它不是身份凭证；user_id 应来自服务端可信身份鉴别，不应从用户提交的表单里直接相信。

若动作可更新多个对象，快照应列明准确目标集合及各目标版本。若目标来自“删除符合条件的全部记录”这类查询，应在确认时冻结目标清单或采用能验证查询结果未漂移的机制，不能在批准后重新执行一个可能返回不同目标的新查询。

4.2 规范化（Canonicalization）

同样的 JSON 内容可能具有不同的键顺序、空白和编码方式。因此需要定义一个明确的规范化过程：

python
import hashlib
import json

def canonical_json(value: dict) -> str:
    return json.dumps(
        value,
        ensure_ascii=False,
        sort_keys=True,
        separators=(",", ":"),
        allow_nan=False,
    )

def fingerprint(value: dict) -> str:
    return hashlib.sha256(canonical_json(value).encode("utf-8")).hexdigest()

要点：

  • 一次确认只绑定某一份已经规范化的完整参数；不能在确认后让模型重新生成参数。
  • SHA-256 指纹有助于发现“预览版本”与“执行版本”不同，但哈希本身不提供用户身份认证；如果攻击者可以同时修改服务端快照和哈希，单纯重新计算哈希不能防止篡改。
  • 可信数据库存储、权限检查、事务约束才是主要安全边界。跨系统流转需要完整性保护时，可以考虑服务器密钥签名/HMAC 或可信的服务间认证。
  • 实际预览若经过模板、Markdown/HTML 渲染、富文本转换、附件转换，则还需要验证可见内容的语义一致性。例如 HTML 中隐藏文字、收件人显示名与实际地址不一致、邮件附件版本不同，都不能只依赖原始 JSON 哈希解决。
  • 不应把包含个人隐私和密钥的完整操作数据直接输出到公共日志。

4.3 预览必须包含关键对象标识

正确的邮件确认信息可以是：

text
操作：发送邮件
发件账户：support@example.org
收件人：user@example.org
抄送：无
密送：无
主题：反馈问题复现步骤
正文：
  你好，以下是我们确认的复现过程：...
附件：无
发送后：无法保证撤回

错误的预览：

text
操作：发送邮件
内容：已为你准备好邮件，请点击确认。

错误原因不是“没有按钮”，而是用户不知道按钮批准了什么。

5. 一次性批准与幂等性

网络错误和双击可以让“确认”请求重复到达，必须避免重复副作用。

一次性批准：同一审批对象只能完成一次从 PENDING 到 APPLIED 或 QUEUED 的有效状态转换。

幂等执行：对于同一个明确业务操作标识，多次确认得到等价的最终效果，例如同一条反馈只被创建一次。

一个典型的数据库条件更新：

sql
UPDATE approvals
SET state = 'CLAIMED'
WHERE approval_id = :approval_id
  AND state = 'PENDING'
  AND expires_at > CURRENT_TIMESTAMP;

然后检查受影响行数是否恰好为 1。不过单独执行这条 SQL 还不够：领取与业务写入必须纳入一致的事务策略，否则可能出现审批已消耗却没有实际业务记录的情况。

可以设计：

  • UNIQUE (approval_id) 防止同一批准重复生成业务操作。
  • UNIQUE (user_id, idempotency_key) 或业务唯一约束，防止相同业务请求重复落库。
  • 资源版本条件更新：WHERE id=? AND version=? 防止对已经变化的数据继续执行旧预览。
  • 对成功的重复确认返回以前的结果，不重复执行；对被拒绝或过期的批准拒绝复活。

跨进程和多 Worker 环境要使用数据库事务、原子条件状态迁移或适用的行锁；单进程内存锁、Python 全局变量不足以提供此保证。

6. TOCTOU：预览到执行之间的竞争

TOCTOU = Time of Check to Time of Use，表示“检查”和“使用”之间对象可能发生变化。

例子：

text
T1：用户看到文档 v7 的预览，准备将标题改成 A
T2：另一用户把该文档更新为 v8
T3：用户确认旧的 v7 预览

如果 T3 不重新检查版本，就可能覆盖 T2 的修改。

正确处理通常是：

  1. 预览时记录资源版本、ETag 或其他可靠的并发控制标识。
  2. 执行前在事务中检查目标仍存在，且用户仍有权限。
  3. 通过条件写入或锁保证检查与更新之间没有竞态。
  4. 对版本冲突返回 409 Conflict 等明确状态，要求重新加载、重新生成预览与重新确认。

PostgreSQL 的 SELECT ... FOR UPDATE 能对选取的行加锁；也可用乐观并发控制：

sql
UPDATE documents
SET body = :new_body,
    version = version + 1
WHERE id = :id
  AND tenant_id = :tenant_id
  AND version = :expected_version
  AND deleted_at IS NULL;

检查受影响记录数是否为 1。数据库隔离级别、触发器、外键级联和其他更新者也会影响具体语义，应结合真实表结构设计。

注意：如果一个对外发送任务已经成功进入 Outbox，后续编辑原始草稿不能悄悄改变已确认的发送内容。Worker 应读取快照中的收件人和正文，不能临时重新读取草稿并发送新版本。

7. 确认者的授权必须独立于模型

存在三种不同权限：

  • 提出请求的权限：可以向 Agent 描述意图。
  • 预览资源的权限：可以查看目标和拟变更内容。
  • 批准和执行权限：可以授权此动作实际产生副作用。

它们不一定相同。比如一名普通员工可以提出删除项目的申请，但只有项目管理员可以批准。

应检查：

  • 经过认证的操作者身份是否符合审批人要求。
  • 租户范围是否一致，资源是否仍属于该租户。
  • 操作工具是否在策略白名单，且属于允许的角色权限。
  • 审批人是否拥有该对象的具体操作权限，而不只是知道 resource_id。
  • 是否涉及超过一定金额、人数或删除范围的二次审批。
  • 操作是否仍符合当前业务状态与政策要求。

真实应用还应考虑 CSRF 防护、身份会话有效期、多因素认证/二次验证（适用于高风险操作）、审批代理机制及审计责任。

对于浏览器端审批，不应接收客户端传回的完整审批快照并直接反序列化执行。客户端应该发送批准 ID 和决定，服务器从可信存储读取原始快照并重新验证。

OpenAI Agents SDK 的 Human-in-the-loop 能暂停工具调用并在确认后续接，但 SDK 的批准状态不能代替应用自己的身份认证、资源授权、快照完整性和重放保护。对于权限变化的运行，持续有效的 always_approve 类许可还可能扩大作用范围，应特别谨慎。

8. 写入：从普通编辑到批量更新

普通写入的预览应包含：

  • 目标资源的稳定 ID、人类可辨识名称及版本。
  • 变更前与变更后的关键字段，以及差异。
  • 原有数据是否被覆盖，是否触发额外副作用。
  • 写入是否可恢复，是否已有其他人修改。

对于文本差异，可以使用 diff；但最终执行器必须以已经冻结的完整最终内容为准，而不是在执行时重新让模型合并 diff。

对于批量更新，应显示明确目标数量和样本，必要时要求展开全量清单。若新记录不断满足筛选条件，不应在确认之后继续将它们纳入同一批准。

9. 删除：软删除、硬删除、级联和恢复

删除不只是调用 DELETE FROM table：

  • 软删除：设置 deleted_at 等标记，通常能够恢复，但仍可能触发索引和业务可见性变化。
  • 硬删除：物理删除数据，恢复依赖备份或审计，未必可撤销。
  • 级联删除：可能同时删除子对象或关联资源。
  • 外部删除：云文件、消息平台等资源删除后未必可以恢复。

预览不仅要显示主对象，还应展示估计影响数量、下游关联和不可逆风险；涉及多人共享资源的批量删除应采取更严格授权。

确认后如目标发生变化，通常应返回冲突，而不是“尝试删除一个名称相同的新对象”。

10. 发送：最重要的是区分入队、发送和送达

发送操作涉及两个系统：本地数据库与外部服务。它们无法天然共享一个数据库事务。

text
用户确认
   ↓
本地事务：冻结邮件内容 + 写入 Outbox
   ↓ commit
状态 QUEUED（不等于已发送）
   ↓
Worker 读取 Outbox
   ↓
使用冻结的 recipient / subject / body 发送
   ↓
外部服务返回成功、失败或未知
   ↓
保存 provider_message_id、状态和审计记录

10.1 Transactional Outbox

在同一数据库事务中写入“已经确认的业务动作”和“待发布/待发送记录”，避免“业务已经提交却忘记发送事件”。Worker 随后读取 Outbox 并发送。该模式依然可能产生至少一次投递，因此需结合幂等性和去重。

10.2 结果未知（UNKNOWN）

设想：

text
Worker 调用了第三方发送接口
第三方已经完成发送
但 Worker 在收到响应前断线

此时本地不知道外部是否真正完成。若盲目重试，可能重复发送。

优先考虑以下方案：

  1. 若供应商支持幂等键，使用稳定的业务键重试，并理解其有效期和请求匹配规则。
  2. 若供应商提供查询接口或回调，先根据第三方消息 ID / 操作 ID 对账。
  3. 如果都不支持，不要声称“绝对只发送一次”；应保留 UNKNOWN 状态，依据风险进行人工核验或受控重试。
  4. 状态区分 QUEUED、SENDING、ACCEPTED_BY_PROVIDER、DELIVERED、FAILED、UNKNOWN，但只有在供应商真实提供相应证据时才标记已送达。

邮件实际送到收件箱还可能涉及投递/退信，HTTP 200 或第三方接受请求通常只能证明其已接收处理请求。

11. “批准一次”不等于“授权未来所有操作”

审批应该限定：

  • 单个操作或明确定义的批次。
  • 特定工具与参数。
  • 特定资源或确切的对象集合。
  • 具体用户/租户与审批人。
  • 有效时间窗口。
  • 可接受的金额、数量和资源成本上限。

不能因为用户允许 Agent 发送一封邮件，就默认批准它以后发送所有邮件。同样，Agent 在暂停审批后不应把已经确认的草稿重新交给模型改写，然后执行新版内容。

如需批量预授权，应将业务策略明确设置在可信程序内，例如仅允许特定收件域、单次最多 N 条、禁止敏感附件，超出阈值必须重新确认。

12. 前端确认 UI 也是安全边界的一部分

后端保存快照只是第一步。实际产品还应保证用户能看到足以做出决策的信息：

  • 防混淆：展示真实邮箱地址/资源 ID，而非仅显示可伪装的昵称或标题。
  • 防隐藏：正文过长时可折叠，但不可隐去关键变更；有附件时显示名称、数量、必要时文件摘要。
  • 防替换：确认按钮对应当前的审批 ID；如果新预览到来，旧确认按钮不能误指向新内容。
  • 防误触：高风险删除可采用二次确认、输入对象名称等机制。
  • 拒绝与修改：拒绝不应执行；点击“编辑”应创建新快照而非修改已确认版本。
  • 无障碍与移动端：确保按钮、内容、提示在不同尺寸下仍然可见、可读、可操作。
  • XSS 防护：工具返回的正文和资源标题来自不可信来源，渲染 HTML 时必须进行上下文相关转义；防止恶意文本伪造确认 UI。

更严格的表述：应用通常能证明“服务器为审批生成了某份完整的预览数据”和“批准对应这一份数据”；如果用户界面存在裁剪、隐藏或渲染错误，不能仅凭服务端哈希就证明用户实际肉眼看到了全部内容。因此生产环境还应把 UI 展示与交互测试纳入质量保证。

13. 工具调用与审批接口如何衔接

一种应用层接口设计如下：

API 方法 功能 主要边界
/actions/preview POST 对模型候选动作校验并生成预览 资源权限、参数、策略
/approvals/{id} GET 返回当前审批预览与状态 审批人授权、敏感内容脱敏
/approvals/{id}/decision POST 接收 approve 或 reject 原子状态转换、过期、并发版本
/operations/{id} GET 查询执行状态和结果 对象级授权
/operations/{id}/retry POST 受控重试 幂等与结果未知审查

对外错误码可以表达：

json
{
  "status": "CONFLICT",
  "code": "RESOURCE_VERSION_CHANGED",
  "message": "待操作资源在确认前已更新，需要重新生成预览。",
  "approval_id": "opaque-id"
}

403：无权限；404：不可见或不存在；409：状态或版本冲突；410：过期审批（也可按接口契约用 409）；422：请求字段不合法；202：外部发送仅已入队。HTTP 状态码和业务状态应共同使用，不宜把所有确认成功都报告为“外部操作已完成”。

14. 审计记录：保留可追溯的真实操作

至少应记录：

  • request_id / run_id / tool_call_id / approval_id / operation_id 的关联。
  • 生成时的工具、对象、参数摘要、资源版本、政策版本。
  • 审批人、审批时间、批准/拒绝决定以及是否过期。
  • 实际执行器使用的冻结参数版本和条件写入结果。
  • 外部服务响应的状态、供应商操作 ID、重试次数与最终结果。
  • 对敏感数据的访问控制、必要脱敏与保留期限。

审计日志应该支持回答：模型想执行什么？用户具体批准了什么？真正执行了什么？它们是否一致？

不能只保存模型说“已经发送成功”的文本；该文本不能代替外部 API 的真实响应和持久化执行记录。

15. 容易误解的五个安全结论

  1. “用户说过允许” ≠ 每一次具体动作都已批准。 授权范围需要明确，尤其是外部副作用。
  2. “有 approval_id” ≠ 有操作权限。 ID 是引用，服务端仍要核验当前登录身份。
  3. “JSON 与哈希相等” ≠ 用户真的看到了完整界面。 还需要可信渲染和展示验证。
  4. “事务提交成功” ≠ 邮件/支付已送达。 数据库与外部系统存在分布式一致性问题。
  5. “重复确认被去重” ≠ 外部接口绝对不会重复执行。 还需要外部幂等能力、回执核验与状态恢复。

16. 示例架构与技术适用范围

后文附上的演示采用 Python 标准库 sqlite3 完成：

  • 冻结写入、软删除与发送草稿快照。
  • 绑定用户、租户、目标对象与资源版本。
  • 确认和拒绝、过期控制、一次性状态转换。
  • 写入/删除直接使用事务完成；发送只入队到 Outbox。
  • 检查重复确认、资源版本冲突和授权失败。

重要限制： 演示中 Actor 是由测试代码直接构造的，生产环境应由可信认证中间件建立身份；SQLite 用于便于教学的本地事务示例，未等同于 PostgreSQL 分布式部署测试；SEND 仅将冻结消息写入 Outbox，没有发送真实邮件。用户界面的真实渲染、真实第三方 API、异步任务消费者及故障后对账需要进一步集成实现。

17. 工程进一步深化：多审批人、跨系统与策略版本

17.1 多人批准

对于资金操作、公开发布与批量删除，可能要求两个不同角色的批准。此时不能把多个布尔值简单相加，必须为审批步骤保存参与者、角色、执行顺序、撤销条件与冲突规则，并防止同一身份重复签署。

17.2 审批期间策略改变

如果管理员撤销了用户权限、工具被禁用或合规政策变更，旧审批不应绕过新的限制。执行前需要重新校验当前硬性规则，而不是只看审批创建时的策略版本。某些变化可能导致审批必须失效并重新展示。

17.3 分布式运行状态恢复

Agent 可在“等待批准”阶段暂停，而 HTTP 连接不必一直保持。恢复运行时，从可信服务端持久化存储读取待确认状态，先核验审批权限与操作快照，再续接。同一状态不能被两个 Worker 同时消费执行。

17.4 真实环境中的复合副作用

比如“修改商品价格并通知所有客户”，包含数据库修改与外部群发，无法天然原子化。可以拆为：

  1. 本地事务提交商品新价格与待通知消息。
  2. Outbox Worker 可靠发送。
  3. 为每个收件人保留明确发送记录和去重键。
  4. 发生部分失败时给出真实的成功数、失败数与未知数。

这类操作要预先明确“批准的是最终目标状态，还是批准某批具体单次动作”，否则在恢复重试时容易超出确认范围。

18. 核心结论

确认机制不是在工具调用前加一个按钮，而是为副作用建立完整的可验证协议。

可信系统必须同时满足：

  • 确认对象明确：操作名称、目标、内容、版本、影响范围清楚。
  • 确认权限明确：操作者与审批人身份可信且持续授权。
  • 确认内容不可悄悄变化：预览快照和执行参数同源。
  • 执行只发生一次或具有幂等保障：重复确认不重复落库。
  • 并发状态可检测：资源版本变化必须冲突或重新确认。
  • 外部副作用有真实状态：入队、发送、接受、交付各自区分。
  • 审计记录可核查：能对照批准前后的真实内容和实际结果。

python
"""Teaching demo for server-owned action previews and one-time confirmations.

SQLite is used for local, deterministic demonstration. No network sending occurs.
"""
from __future__ import annotations

import hashlib
import json
import sqlite3
import time
import uuid
from contextlib import contextmanager
from dataclasses import dataclass
from pathlib import Path


class ApprovalError(Exception):
    pass


class Forbidden(ApprovalError):
    pass


class Expired(ApprovalError):
    pass


class Conflict(ApprovalError):
    pass


class InvalidDecision(ApprovalError):
    pass


@dataclass(frozen=True)
class Actor:
    user_id: str
    tenant_id: str


def canonical(data: dict) -> str:
    return json.dumps(data, ensure_ascii=False, sort_keys=True, separators=(",", ":"), allow_nan=False)


def digest(payload_json: str) -> str:
    return hashlib.sha256(payload_json.encode("utf-8")).hexdigest()


class ApprovalDB:
    def __init__(self, filename: str | Path):
        self.filename = str(filename)
        self._create_schema()

    @contextmanager
    def connection(self):
        conn = sqlite3.connect(self.filename, timeout=5.0)
        conn.row_factory = sqlite3.Row
        conn.execute("PRAGMA foreign_keys = ON")
        try:
            yield conn
        finally:
            conn.close()

    @contextmanager
    def transaction(self):
        with self.connection() as conn:
            conn.execute("BEGIN IMMEDIATE")
            try:
                yield conn
                conn.commit()
            except BaseException:
                conn.rollback()
                raise

    def _create_schema(self):
        with self.connection() as conn:
            conn.executescript("""
                CREATE TABLE IF NOT EXISTS documents (
                    id TEXT PRIMARY KEY,
                    tenant_id TEXT NOT NULL,
                    owner_id TEXT NOT NULL,
                    body TEXT NOT NULL,
                    version INTEGER NOT NULL DEFAULT 1,
                    deleted INTEGER NOT NULL DEFAULT 0
                );
                CREATE TABLE IF NOT EXISTS drafts (
                    id TEXT PRIMARY KEY,
                    tenant_id TEXT NOT NULL,
                    owner_id TEXT NOT NULL,
                    recipient TEXT NOT NULL,
                    subject TEXT NOT NULL,
                    body TEXT NOT NULL,
                    version INTEGER NOT NULL DEFAULT 1
                );
                CREATE TABLE IF NOT EXISTS approvals (
                    id TEXT PRIMARY KEY,
                    tenant_id TEXT NOT NULL,
                    user_id TEXT NOT NULL,
                    action TEXT NOT NULL,
                    target_id TEXT NOT NULL,
                    expected_version INTEGER NOT NULL,
                    payload_json TEXT NOT NULL,
                    payload_hash TEXT NOT NULL,
                    expires_at REAL NOT NULL,
                    state TEXT NOT NULL DEFAULT 'PENDING',
                    result TEXT
                );
                CREATE TABLE IF NOT EXISTS outbox (
                    approval_id TEXT PRIMARY KEY REFERENCES approvals(id),
                    message_json TEXT NOT NULL,
                    state TEXT NOT NULL DEFAULT 'QUEUED'
                );
                CREATE TABLE IF NOT EXISTS audit (
                    id INTEGER PRIMARY KEY AUTOINCREMENT,
                    approval_id TEXT NOT NULL,
                    event TEXT NOT NULL,
                    happened_at REAL NOT NULL
                );
            """)

    def put_document(self, actor: Actor, id: str, body: str):
        with self.transaction() as conn:
            conn.execute("INSERT INTO documents(id,tenant_id,owner_id,body) VALUES(?,?,?,?)",
                         (id, actor.tenant_id, actor.user_id, body))

    def put_draft(self, actor: Actor, id: str, recipient: str, subject: str, body: str):
        with self.transaction() as conn:
            conn.execute("INSERT INTO drafts(id,tenant_id,owner_id,recipient,subject,body) VALUES(?,?,?,?,?,?)",
                         (id, actor.tenant_id, actor.user_id, recipient, subject, body))

    @staticmethod
    def _owned(conn, table: str, actor: Actor, target_id: str):
        if table not in ('documents', 'drafts'):
            raise ValueError('unapproved table')
        row = conn.execute(f"SELECT * FROM {table} WHERE id=? AND tenant_id=? AND owner_id=?",
                           (target_id, actor.tenant_id, actor.user_id)).fetchone()
        if row is None or (table == 'documents' and row['deleted']):
            raise Forbidden('resource not accessible')
        return row

    def prepare(self, actor: Actor, action: str, target_id: str, *, new_body: str | None = None,
                ttl_seconds: float = 300) -> dict:
        if action not in ('WRITE', 'DELETE', 'SEND'):
            raise ValueError('unsupported action')
        if ttl_seconds <= 0:
            raise ValueError('ttl must be positive')
        with self.transaction() as conn:
            table = 'drafts' if action == 'SEND' else 'documents'
            row = self._owned(conn, table, actor, target_id)
            if action == 'WRITE':
                if new_body is None or not new_body.strip():
                    raise ValueError('new body must be nonempty')
                payload = {'action': action, 'document_id': target_id,
                           'old_body': row['body'], 'new_body': new_body, 'version': row['version']}
            elif action == 'DELETE':
                payload = {'action': action, 'document_id': target_id,
                           'old_body': row['body'], 'version': row['version']}
            else:
                payload = {'action': action, 'draft_id': target_id,
                           'to': row['recipient'], 'subject': row['subject'],
                           'body': row['body'], 'version': row['version']}
            payload_json = canonical(payload)
            approval_id = uuid.uuid4().hex
            conn.execute("""INSERT INTO approvals
                (id,tenant_id,user_id,action,target_id,expected_version,payload_json,payload_hash,expires_at)
                VALUES(?,?,?,?,?,?,?,?,?)""",
                (approval_id, actor.tenant_id, actor.user_id, action, target_id,
                 row['version'], payload_json, digest(payload_json), time.time() + ttl_seconds))
            conn.execute('INSERT INTO audit(approval_id,event,happened_at) VALUES(?,?,?)',
                         (approval_id, 'PREPARED', time.time()))
            return {'approval_id': approval_id, 'display': payload,
                    'fingerprint': digest(payload_json)}

    def decide(self, actor: Actor, approval_id: str, approved: bool) -> str:
        if not isinstance(approved, bool):
            raise InvalidDecision('approval decision must be boolean')
        with self.transaction() as conn:
            approval = conn.execute('SELECT * FROM approvals WHERE id=?', (approval_id,)).fetchone()
            if approval is None or approval['user_id'] != actor.user_id or approval['tenant_id'] != actor.tenant_id:
                raise Forbidden('approval not accessible')
            if approval['state'] in ('APPLIED', 'QUEUED'):
                if approved:
                    return approval['result']
                raise Conflict('already executed')
            if approval['state'] == 'REJECTED':
                if not approved:
                    return 'REJECTED'
                raise Conflict('already rejected')
            if approval['state'] != 'PENDING':
                raise Conflict('invalid state')
            if time.time() >= approval['expires_at']:
                conn.execute("UPDATE approvals SET state='EXPIRED' WHERE id=?", (approval_id,))
                conn.execute('INSERT INTO audit(approval_id,event,happened_at) VALUES(?,?,?)',
                             (approval_id, 'EXPIRED', time.time()))
                return 'EXPIRED'
            if not approved:
                conn.execute("UPDATE approvals SET state='REJECTED',result='REJECTED' WHERE id=?", (approval_id,))
                conn.execute('INSERT INTO audit(approval_id,event,happened_at) VALUES(?,?,?)',
                             (approval_id, 'REJECTED', time.time()))
                return 'REJECTED'

            action = approval['action']
            table = 'drafts' if action == 'SEND' else 'documents'
            resource = self._owned(conn, table, actor, approval['target_id'])
            payload_json = approval['payload_json']
            if digest(payload_json) != approval['payload_hash']:
                raise Conflict('preview integrity mismatch')
            payload = json.loads(payload_json)
            if resource['version'] != approval['expected_version']:
                raise Conflict('resource changed after preview')
            # In this demo the full current source is also compared to the stored snapshot.
            if action in ('WRITE', 'DELETE') and resource['body'] != payload['old_body']:
                raise Conflict('current content differs from preview')
            if action == 'WRITE':
                rowcount = conn.execute("""UPDATE documents SET body=?,version=version+1
                    WHERE id=? AND tenant_id=? AND owner_id=? AND version=? AND deleted=0""",
                    (payload['new_body'], approval['target_id'], actor.tenant_id, actor.user_id,
                     approval['expected_version'])).rowcount
                result, state = 'APPLIED', 'APPLIED'
            elif action == 'DELETE':
                rowcount = conn.execute("""UPDATE documents SET deleted=1,version=version+1
                    WHERE id=? AND tenant_id=? AND owner_id=? AND version=? AND deleted=0""",
                    (approval['target_id'], actor.tenant_id, actor.user_id,
                     approval['expected_version'])).rowcount
                result, state = 'APPLIED', 'APPLIED'
            else:
                current = {'action': 'SEND', 'draft_id': resource['id'],
                           'to': resource['recipient'], 'subject': resource['subject'],
                           'body': resource['body'], 'version': resource['version']}
                if canonical(current) != payload_json:
                    raise Conflict('draft differs from preview')
                conn.execute('INSERT INTO outbox(approval_id,message_json) VALUES(?,?)',
                             (approval_id, payload_json))
                rowcount = 1
                result, state = 'QUEUED', 'QUEUED'
            if rowcount != 1:
                raise Conflict('concurrent modification')
            conn.execute('UPDATE approvals SET state=?,result=? WHERE id=? AND state=\'PENDING\'',
                         (state, result, approval_id))
            conn.execute('INSERT INTO audit(approval_id,event,happened_at) VALUES(?,?,?)',
                         (approval_id, state, time.time()))
            return result

    def get_document(self, id: str) -> tuple[str, int, bool]:
        with self.connection() as conn:
            row = conn.execute('SELECT body,version,deleted FROM documents WHERE id=?', (id,)).fetchone()
            return (row['body'], row['version'], bool(row['deleted']))

    def outbox_count(self) -> int:
        with self.connection() as conn:
            return conn.execute('SELECT COUNT(*) AS n FROM outbox').fetchone()['n']

    def get_outbox_message(self, approval_id: str) -> dict:
        with self.connection() as conn:
            row = conn.execute('SELECT message_json FROM outbox WHERE approval_id=?', (approval_id,)).fetchone()
            if row is None:
                raise ValueError('no message queued')
            return json.loads(row['message_json'])

import sqlite3
import tempfile
import time
import unittest
from pathlib import Path
from approval_example import ApprovalDB, Actor, Forbidden, Conflict, InvalidDecision


class ApprovalTests(unittest.TestCase):
    def setUp(self):
        self.tmp = tempfile.TemporaryDirectory()
        self.addCleanup(self.tmp.cleanup)
        self.db = ApprovalDB(Path(self.tmp.name) / 'test.db')
        self.alice = Actor('alice', 'org1')
        self.bob = Actor('bob', 'org1')
        self.external = Actor('alice', 'org2')
        self.db.put_document(self.alice, 'doc1', 'Original')
        self.db.put_draft(self.alice, 'draft1', 'user@example.org', 'Subject', 'Mail body')

    def test_update_exact_preview(self):
        p = self.db.prepare(self.alice, 'WRITE', 'doc1', new_body='Revised')
        self.assertEqual(p['display']['new_body'], 'Revised')
        self.assertEqual(self.db.decide(self.alice, p['approval_id'], True), 'APPLIED')
        self.assertEqual(self.db.get_document('doc1'), ('Revised', 2, False))

    def test_repeat_confirmation_is_idempotent(self):
        p = self.db.prepare(self.alice, 'WRITE', 'doc1', new_body='Revised')
        self.db.decide(self.alice, p['approval_id'], True)
        self.assertEqual(self.db.decide(self.alice, p['approval_id'], True), 'APPLIED')
        self.assertEqual(self.db.get_document('doc1')[1], 2)

    def test_delete_is_soft(self):
        p = self.db.prepare(self.alice, 'DELETE', 'doc1')
        self.assertEqual(self.db.decide(self.alice, p['approval_id'], True), 'APPLIED')
        self.assertTrue(self.db.get_document('doc1')[2])

    def test_reject_does_not_modify(self):
        p = self.db.prepare(self.alice, 'DELETE', 'doc1')
        self.assertEqual(self.db.decide(self.alice, p['approval_id'], False), 'REJECTED')
        self.assertEqual(self.db.get_document('doc1'), ('Original', 1, False))

    def test_rejected_cannot_be_approved(self):
        p = self.db.prepare(self.alice, 'DELETE', 'doc1')
        self.db.decide(self.alice, p['approval_id'], False)
        with self.assertRaises(Conflict):
            self.db.decide(self.alice, p['approval_id'], True)

    def test_cross_user_denied(self):
        p = self.db.prepare(self.alice, 'DELETE', 'doc1')
        with self.assertRaises(Forbidden):
            self.db.decide(self.bob, p['approval_id'], True)
        with self.assertRaises(Forbidden):
            self.db.prepare(self.bob, 'DELETE', 'doc1')

    def test_cross_tenant_denied(self):
        p = self.db.prepare(self.alice, 'DELETE', 'doc1')
        with self.assertRaises(Forbidden):
            self.db.decide(self.external, p['approval_id'], True)

    def test_expired(self):
        p = self.db.prepare(self.alice, 'DELETE', 'doc1', ttl_seconds=0.001)
        time.sleep(0.01)
        self.assertEqual(self.db.decide(self.alice, p['approval_id'], True), 'EXPIRED')
        self.assertFalse(self.db.get_document('doc1')[2])

    def test_resource_version_conflict(self):
        p1 = self.db.prepare(self.alice, 'WRITE', 'doc1', new_body='A')
        p2 = self.db.prepare(self.alice, 'WRITE', 'doc1', new_body='B')
        self.db.decide(self.alice, p1['approval_id'], True)
        with self.assertRaises(Conflict):
            self.db.decide(self.alice, p2['approval_id'], True)
        self.assertEqual(self.db.get_document('doc1')[0], 'A')

    def test_confirmation_does_not_accept_changed_payload(self):
        p = self.db.prepare(self.alice, 'WRITE', 'doc1', new_body='Approved')
        # Client cannot supply replacement target or content to decide().
        with self.assertRaises(TypeError):
            self.db.decide(self.alice, p['approval_id'], True, new_body='Malicious')
        self.assertEqual(self.db.decide(self.alice, p['approval_id'], True), 'APPLIED')
        self.assertEqual(self.db.get_document('doc1')[0], 'Approved')

    def test_send_only_queues(self):
        p = self.db.prepare(self.alice, 'SEND', 'draft1')
        self.assertEqual(self.db.decide(self.alice, p['approval_id'], True), 'QUEUED')
        self.assertEqual(self.db.outbox_count(), 1)
        self.assertEqual(self.db.get_outbox_message(p['approval_id'])['to'], 'user@example.org')

    def test_send_duplicate_no_duplicate_outbox(self):
        p = self.db.prepare(self.alice, 'SEND', 'draft1')
        self.db.decide(self.alice, p['approval_id'], True)
        self.assertEqual(self.db.decide(self.alice, p['approval_id'], True), 'QUEUED')
        self.assertEqual(self.db.outbox_count(), 1)

    def test_send_draft_change_disallowed(self):
        p = self.db.prepare(self.alice, 'SEND', 'draft1')
        with self.db.transaction() as conn:
            conn.execute("UPDATE drafts SET recipient='changed@example.org', version=version+1 WHERE id='draft1'")
        with self.assertRaises(Conflict):
            self.db.decide(self.alice, p['approval_id'], True)
        self.assertEqual(self.db.outbox_count(), 0)

    def test_no_boolean_coercion(self):
        p = self.db.prepare(self.alice, 'DELETE', 'doc1')
        with self.assertRaises(InvalidDecision):
            self.db.decide(self.alice, p['approval_id'], 'true')

    def test_preview_fingerprint_integrity(self):
        p = self.db.prepare(self.alice, 'WRITE', 'doc1', new_body='New')
        with self.db.transaction() as conn:
            conn.execute('UPDATE approvals SET payload_json=? WHERE id=?', ('{"tampered":true}', p['approval_id']))
        with self.assertRaises(Conflict):
            self.db.decide(self.alice, p['approval_id'], True)

    def test_actor_mutations_not_taken_from_confirmation(self):
        p = self.db.prepare(self.alice, 'DELETE', 'doc1')
        self.assertEqual(self.db.decide(self.alice, p['approval_id'], True), 'APPLIED')
        with self.assertRaises(Conflict):
            self.db.decide(self.alice, p['approval_id'], False)
