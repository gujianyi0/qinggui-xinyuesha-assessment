# 测试、部署与效果验证（二）：可控模型替身、故障模拟与不依赖付费模型的自动化测试

> 对应学习目标：**用可控的模型替身模拟超时、非法 JSON、缺字段、工具错误和暂时失败，让常规测试不依赖付费模型调用。**  
> 知识范围：Python 3.13、pytest、asyncio、Pydantic v2、FastAPI、HTTPX；示例以一次结构化 AI 问答及受控工具调用为主。  
> 文档性质：技术知识手册，独立于其他章节。示例中的模型响应和工具数据是人工构造，不代表真实模型行为或真实业务事实。

## 1. 为什么 AI 应用测试不能完全依赖真实模型

AI 应用同时包含**确定性程序**与**概率性模型输出**。例如，程序可以确定某个字段是否存在、是否应触发重试、是否应拒绝非法工具参数；而模型下一次是否选择某项工具、是否回答正确，则会受到模型版本、采样、上下文、工具描述等影响。

若每次 `pytest` 运行都调用真实模型，将产生若干工程问题：

1. **非确定性**：同一输入可能得到不同措辞、不同结构甚至不同工具选择，导致测试结果不稳定。
2. **外部依赖**：网络、DNS、服务商可用性、API 配额和密钥状态均可能影响测试。
3. **成本**：付费调用可能使大量单元测试和 CI 重跑产生额外费用。
4. **时间**：测试耗时与网络和模型生成速度有关，反馈变慢。
5. **故障难以复现**：真实模型未必恰好返回非法 JSON、超时或工具异常。
6. **定位困难**：测试失败可能来自代码修改，也可能来自外部服务变化。

因此常规自动化测试应在**可控制的接口边界**替换真实模型。待程序逻辑稳定后，再以少量真实模型测试校验真实供应商协议和模型效果。

这不意味着不测试真实模型；而是把**程序可靠性测试**和**模型行为评测**分开。

## 2. Test Double 的概念与分类

Test Double 是测试替身的总称。严格的分类更多用于解释设计意图，实际工具库常将它们统一称为 Mock。

| 类型 | 主要用途 | 例子 |
|---|---|---|
| Dummy | 只为满足参数结构，不参与业务逻辑 | 不会被使用的占位工具对象 |
| Stub | 按预设输入或脚本返回固定结果 | `complete()` 永远返回合法结构化响应 |
| Fake | 具有简化但可运行的行为 | 内存中的游戏规则数据库 |
| Mock | 记录调用并断言交互行为 | 验证 `complete()` 恰好被 `await` 一次 |
| Spy | 包装真实或替代实现，记录调用细节 | 保留工具调用参数、顺序、耗时 |

**选择标准**：如果要验证返回值，用 Stub/Fake；如果要验证“有没有调用、调用几次、参数是否正确”，用 Mock/Spy。常规工程可以混合使用。

需要注意：`unittest.mock.Mock` 这个 Python 类不只用于狭义 Mock，也能够担任 Stub 等替身角色。`AsyncMock` 则用于替代异步函数或方法。

## 3. 测试边界：哪些是真实组件，哪些是假组件

设想调用链为：

```text
HTTP 请求
  └─ FastAPI 输入验证（真实）
       └─ ChatService 业务编排（真实）
            ├─ ModelGateway（测试时：ScriptedModel）
            ├─ 输出 JSON / Pydantic 校验（真实）
            ├─ ToolGateway（测试时：FakeTools）
            └─ 结果状态映射（真实）
```

这里被替换的是**最外侧、最昂贵或最不可控的依赖**，而不是被测业务代码。否则测试只验证“替身返回预期值”，无法证明真实代码能处理异常。

一个较好的测试样本会明确写出：

- **Given：** 模型第一次返回 503 类临时异常，第二次返回合法 JSON。
- **When：** 调用 `ChatService.ask()`。
- **Then：** 系统最终成功、模型调用次数等于 2、工具未被误调用。

每个断言都对应可观察结果，不应只写“没有抛异常”。

## 4. 用 Protocol 和依赖注入定义稳定的模型接口

业务层不应该直接依赖某个具体服务商 SDK 的所有响应字段。可以先抽象如下接口：

```python
from typing import Protocol

class ModelGateway(Protocol):
    async def complete(self, prompt: str, tool_result: dict | None = None):
        ...
```

生产环境由 SDK Adapter 实现；测试环境由脚本替身实现。

调用关系应是：

```text
ChatService ─依赖─> ModelGateway 接口
                      ↑             ↑
               RealModelAdapter  ScriptedModel
```

这样不必修改业务代码就能切换模型实现。其原则是**显式依赖注入**：将外部对象作为构造参数或函数参数传入，而不是让业务代码在内部直接读取 API Key 并初始化供应商客户端。

`Protocol` 主要服务于结构化类型检查；它本身不会阻止测试对象在运行时实现错误。应通过测试和静态类型工具共同验证契约。

## 5. 可控脚本模型：按预定顺序返回响应或抛出异常

最通用的教学替身是一个“响应队列”：

```python
class ScriptedModel:
    def __init__(self, *actions):
        self._actions = list(actions)
        self.call_args = []

    async def complete(self, prompt, tool_result=None):
        self.call_args.append((prompt, tool_result))
        if not self._actions:
            raise AssertionError("script exhausted")
        action = self._actions.pop(0)
        if isinstance(action, Exception):
            raise action
        if callable(action):
            return await action(prompt, tool_result)
        return action
```

构造三个可控返回：

- 第一次调用：抛出 `TemporaryProviderError`。
- 第二次调用：返回合法结构化答案。
- 若错误地发生第三次调用：立即抛出 `AssertionError`。

这样既可以测试最终结果，也可以检测错误的多余调用。每个测试单独创建替身，避免多个测试或多个并发任务共享可变脚本队列。

## 6. 区分模型响应的五类故障

### 6.1 非法 JSON

```text
{"status":"answered","answer":
```

此时 JSON 语法无法解析；应返回独立的 `invalid_json` 状态，不能把原始文本当作可靠数据继续使用。

### 6.2 缺失必填字段

```json
{"status":"answered", "answer":"已查到", "citations":["rule-v1"]}
```

如果业务要求 `missing_fields` 字段必须存在，即使 JSON 合法也应返回 `missing_field`。这应与字段类型错误区分，便于监控和定位。

### 6.3 字段类型或业务语义错误

```json
{"status":"answered", "answer":123, "citations":["rule-v1"], "missing_fields":[]}
```

字段类型与 Schema 不符。另一个例子是 `status="answered"` 但 `citations=[]`，它可能类型完全正确，却违反了“答案必须具备来源”的业务契约。

### 6.4 模型拒答

供应商可能在专门的 refusal 字段、响应状态或正文中表示拒答。可靠适配器应优先读取供应商的结构化拒答信号，而不是把所有拒答都当作 JSON 解析失败。模拟替身的 `refused=True` 用于验证应用分流行为。

### 6.5 信息不足

信息不足并不等于模型或程序失败。可以返回：

```json
{
  "status": "needs_more_info",
  "answer": null,
  "citations": [],
  "missing_fields": ["游戏版本"]
}
```

前端此时可以提示用户补充版本号，而不是报“服务器异常”。

## 7. Pydantic v2 的严格 Schema 与跨字段校验

```python
from typing import Literal
from pydantic import BaseModel, ConfigDict, model_validator

class AnswerPayload(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)
    status: Literal["answered", "needs_more_info"]
    answer: str | None
    citations: list[str]
    missing_fields: list[str]

    @model_validator(mode="after")
    def consistent(self):
        if self.status == "answered" and (not self.answer or not self.citations):
            raise ValueError("answered requires content and citations")
        if self.status == "needs_more_info" and not self.missing_fields:
            raise ValueError("missing_fields required")
        return self
```

`extra="forbid"` 阻止未知字段；`strict=True` 减少意外类型转换；`model_validator` 处理单个字段约束无法表达的跨字段关系。

在测试中应区分：

| 分类 | 例子 | 预期 |
|---|---|---|
| JSON 解析失败 | JSON 被截断 | `invalid_json` |
| 结构缺字段 | 缺 `missing_fields` | `missing_field` |
| 类型错误 | `answer=123` | `invalid_schema` |
| 跨字段错误 | 有答案却无引用 | `invalid_schema` |
| 拒答 | `refused=True` | `model_refusal` |
| 信息不足 | `status=needs_more_info` | `needs_more_info` |

**局限性**：通过 Pydantic 只能验证格式和定义的业务约束，不能证明 `citations` 对应的原文真实支持答案。来源真实性和引用支持仍须由独立证据核验完成。

## 8. 模拟超时：抛异常与真实超时等待是两种测试

最简单的超时替身可以直接抛出 `TimeoutError`：

```python
async def complete(...):
    raise TimeoutError("simulated timeout")
```

它能验证**异常分类和重试分支**，但不能证明你的 `asyncio.wait_for()` 真的能取消长时间挂起的协程。

更接近异步机制的测试是：

```python
import asyncio

async def never_finishes(prompt, tool_result):
    await asyncio.Event().wait()

# ChatService 使用：
# await asyncio.wait_for(model.complete(...), timeout=0.01)
```

需要测试：超时结果状态、有限重试次数，以及被等待协程的 `finally` 清理能否执行。

**细节：** `asyncio.wait_for()` 会向等待目标发出取消，但取消是协作式的；若目标不正确处理取消，真实完成时间可能超过设定超时时间。模型服务商在远程服务器上已经开始的请求也未必随本地取消立即结束。因此单元测试中的“取消成功”不能推导出远程调用绝对没有成本。

不推荐让每项测试真正 `sleep(30)`。大部分分支用脚本异常或可控虚拟时钟验证，只有少量底层取消测试才使用极短等待。

## 9. 暂时性故障与有限重试

需要把故障分成至少两类：

- **临时性故障**：供应商短暂不可用、部分 5xx、限流且允许稍后重试、暂时性网络异常。
- **永久性故障**：认证失败、参数非法、模型不存在、业务权限拒绝；通常不应无意义地重试。

示例：

```python
model = ScriptedModel(
    TemporaryProviderError("provider temporarily unavailable"),
    ModelReply(text='{"status":"answered","answer":"成功","citations":["rule-v1"],"missing_fields":[]}')
)
```

在 `max_attempts=2` 的前提下，预期是“调用两次，第二次成功”；若连续两次暂时失败，应有独立的耗尽状态，而不是无限重试。

生产级重试还需考虑：

1. 最多尝试次数和总截止时间。
2. 指数退避、随机抖动与服务商 `Retry-After`。
3. 并发限流和重试风暴。
4. 幂等性：写入、发送等具有副作用的工具不可在结果未知时盲目重试。
5. SDK 自带的内部重试：避免应用层与 SDK 叠加形成意外的调用倍数。

本章示例默认 `retry_delay=0`，目的是让**故障分支测试快速且确定**；不应将它作为生产服务的完整重试策略。

## 10. 模拟工具调用错误

模型提出的工具调用与真实工具执行是两层对象：

```text
模型返回：lookup_rule(rule_id="r1")
      ↓
程序校验工具白名单及参数 Schema
      ↓
FakeTools.lookup_rule("r1")
      ↓
返回数据、抛出 ToolExecutionError，或拒绝无效调用
      ↓
应用分类处理，并决定是否再次请求模型
```

应至少覆盖：

- 工具成功：结果原样回传到下一次模型调用。
- 工具执行失败：返回 `tool_error`，明确记录已调用工具次数。
- 未注册工具：返回 `invalid_tool`，**不得调用真实工具**。
- 工具参数类型不合法：返回 `invalid_tool_arguments`，**不得执行**。
- 超出工具步数预算：拒绝新的工具调用。

测试工具失败时，不能只给模型一个“虚构的工具失败文本”就声称测试了工具层错误。更好的做法是让 Fake Tool 真正抛出指定异常，从而运行服务的异常处理代码。

## 11. AsyncMock、Mock 与调用断言

Python 标准库提供 `unittest.mock.AsyncMock`：

```python
from unittest.mock import AsyncMock

model = AsyncMock()
model.complete.return_value = ModelReply(text=valid_json)

result = await ChatService(model, FakeTools()).ask("规则?")
assert result.status == "success"
model.complete.assert_awaited_once_with("规则?", None)
```

要理解四类不同检查：

- `call_count`：方法被调用了几次。
- `await_count`：异步方法返回的协程被等待了几次。
- `assert_awaited_once_with()`：异步调用是否被正确等待且参数一致。
- `side_effect`：让替身按顺序返回不同结果或抛异常。

异步函数“被调用”不意味着其协程“已经运行完成”；验证 `await` 通常比只验证调用更贴近业务意图。`AsyncMock` 的这些行为由 Python 官方文档定义。

## 12. pytest Fixture、parametrize 与 monkeypatch 的职责

- `fixture` 创建隔离的测试对象，准备、恢复环境与资源。
- `parametrize` 用相同逻辑测试多个错误输入。
- `monkeypatch` 临时替换模块属性、环境变量或字典条目。
- `AsyncMock` 用于断言异步调用的交互。
- 依赖注入更适合受控的新系统；`monkeypatch` 有助于测试不易重构的既有代码。

例如使用 `pytest.mark.parametrize`：

```python
@pytest.mark.parametrize("raw,expected", [
    ('{"answer":', "invalid_json"),
    ('{"status":"answered"}', "missing_field"),
])
@pytest.mark.asyncio
async def test_malformed_results(raw, expected):
    svc = ChatService(ScriptedModel(ModelReply(text=raw)), FakeTools())
    assert (await svc.ask("x")).status == expected
```

如果必须打补丁，应该替换**被测模块实际引用的名称**，而不是随意修改标准库全局方法。pytest 的 `monkeypatch` 会在测试结束时恢复修改。

## 13. FastAPI：用 dependency_overrides 替换真实模型依赖

对于 FastAPI，最好让路由只负责输入输出契约，业务逻辑通过依赖注入取得：

```python
async def get_chat_service() -> ChatService:
    raise RuntimeError("Production must configure a real gateway")

@app.post("/ask")
async def ask(body: AskRequest, service: Annotated[ChatService, Depends(get_chat_service)]):
    result = await service.ask(body.prompt)
    return {"status": result.status, "answer": ...}
```

测试中：

```python
app.dependency_overrides[get_chat_service] = lambda: fake_service
try:
    with TestClient(app) as client:
        response = client.post("/ask", json={"prompt": "规则?"})
    assert response.status_code == 200
finally:
    app.dependency_overrides.clear()
```

本示例用 HTTP 200 承载不同业务状态，便于直观观察状态分流。**这不是唯一或通用的 HTTP 错误映射策略**：生产环境应根据接口契约决定模型超时映射为 504、依赖不可用映射为 503 或统一状态协议；无论如何不能把业务成功和网络成功混淆。

`dependency_overrides` 是 FastAPI 官方推荐的外部依赖替换机制，适合测试模型服务、用户身份与其他外部接口。

## 14. HTTPX MockTransport：模拟 HTTP 层而不是只模拟业务返回值

仅模拟 `ModelGateway.complete()` 无法测试真实 SDK Adapter 是否正确读取 HTTP 状态码、响应头和原始响应结构。

需要进一步验证 HTTP 客户端时，可以使用 `httpx.MockTransport`：

```python
import httpx

def handler(request: httpx.Request) -> httpx.Response:
    assert request.url.path == "/v1/chat"
    return httpx.Response(200, json={"choices": [{"message": {"content": "example"}}]})

transport = httpx.MockTransport(handler)
with httpx.Client(transport=transport, base_url="https://fake.invalid") as client:
    response = client.post("/v1/chat", json={"model": "fixture"})
assert response.status_code == 200
```

注意：它模拟的是 HTTP 客户端接收到的响应，并非真实网络连接。HTTPX 也有用于流式事件和异步客户端的测试方案；对于复杂异步 HTTP Mock，可使用专门的配套库或测试 Transport。

## 15. 纯替身测试、HTTP 契约测试与真实模型评测的边界

| 层级 | 真实运行的部分 | 可验证内容 | 无法证明 |
|---|---|---|---|
| 业务单元测试 | ChatService、Pydantic、状态映射 | 错误分类、重试、预算 | 真实供应商协议 |
| API 集成测试 | FastAPI、业务层、假模型 | 路由、响应契约、校验、异常传播 | 外部模型服务表现 |
| HTTP 契约测试 | 实际 HTTP Adapter + MockTransport | HTTP 编码、解析、状态码映射 | 真正的远端可用性 |
| 供应商联通冒烟测试 | 真实 SDK + 真实 API | 密钥、模型名、网络、基本响应 | 大规模准确率 |
| 真实模型效果评测 | 模型 + 固定问题集 + 证据 | 正确率、工具选择、引用质量 | 所有未覆盖的情形 |
| 压力/故障恢复测试 | 真实服务组合 | 并发容量、恢复时间、资源消耗 | 所有生产故障 |

**不可用 Mock 单独证明**：真实模型一定会生成符合 Schema 的 JSON；模型从不幻觉；真实 API 一定可以取消远端生成；工具选择一定正确。

## 16. 测试设计：错误码、调用次数、资源状态一起断言

一个合格的异常测试至少应回答：

1. **结果状态**：最终是 `invalid_json`、`model_timeout`，还是 `provider_unavailable`？
2. **调用次数**：触发了几次真实业务调用？是否产生多余重试？
3. **安全边界**：无效工具参数有没有被执行？是否产生未授权副作用？
4. **资源边界**：超时后协程是否收到取消？连接是否按设计关闭？
5. **调用方契约**：前端能否明确知道哪些情况可重试、哪些需要补充资料？
6. **数据隔离**：测试之间是否重置模型脚本、工具记录和依赖替换？

### 推荐的核心故障矩阵

| 模拟输入 | 预期应用状态 | 是否重试模型 | 预期工具执行 |
|---|---|---|---|
| 合法 JSON | `success` | 否 | 视调用流程 |
| 非法 JSON | `invalid_json` | 本示例否 | 否 |
| 必填字段缺失 | `missing_field` | 本示例否 | 否 |
| 结构类型错误 | `invalid_schema` | 本示例否 | 否 |
| 明确拒答 | `model_refusal` | 否 | 否 |
| 信息不足 | `needs_more_info` | 否 | 否 |
| 生成截断 | `incomplete_output` | 策略决定 | 否 |
| 模型超时 | `model_timeout` | 有界重试 | 否 |
| 临时 503 等价异常 | `provider_unavailable` 或恢复成功 | 有界重试 | 否 |
| 永久请求失败 | `provider_rejected` | 否 | 否 |
| 工具执行异常 | `tool_error` | 不盲目重试写操作 | 一次 |
| 无效工具名称 | `invalid_tool` | 否 | 零次 |
| 无效工具参数 | `invalid_tool_arguments` | 否 | 零次 |

是否尝试修复不合法 JSON，应由独立、可计数的业务策略决定；不能无上限地重新调用模型。

## 17. 流式响应也需要可控替身

本节的完整实现以非流式回答为主。对流式模型，替身还需要控制事件序列，而不只是返回一个字符串。

```python
async def fake_stream():
    yield {"type": "text_delta", "text": "游戏"}
    yield {"type": "text_delta", "text": "规则"}
    yield {"type": "completed", "usage": {"output_tokens": 2}}
```

至少测试：正常增量拼接、部分事件缺失、完成前断开、取消、错误事件、重复终止事件、工具调用参数分片、用量缺失等。**收到文本增量不是生成成功**，只有供应商与应用定义的完成条件成立时才可标记完成。

可使用 `async def` + `yield` 编写异步生成器，在 pytest 中用 `async for` 消费。这类测试同样无需付费 API。

## 18. 确定性、随机种子和并发隔离

即使所有模型响应是假的，测试仍可能不稳定。例如：

- 测试依赖真实系统时间或随机退避，导致时间窗口偶尔不一致。
- 多个测试共享同一个 `ScriptedModel`，彼此消耗预设事件。
- 服务是单例，记录了跨测试的调用历史。
- 并发测试使用固定 `sleep()` 猜测执行顺序。
- 每个测试没有恢复 `dependency_overrides`。
- 异步任务尚未退出，下一测试又读取相同资源。

改进方法是每个测试独立创建 Model Fake 和 Tool Fake；通过 `Event` 或可注入时钟控制顺序；为随机数设置明确种子；每次测试恢复全局依赖状态；使用 `finally` 和 fixture teardown 清理异步任务。

`AsyncMock` 和脚本队列本身不保证在多个并发调用下的脚本分配顺序。因此不要把“按脚本顺序消耗响应”误认为“并发任务实际完成顺序”。

## 19. CI 中保证常规测试不意外产生费用

推荐将测试分成不同类别：

```text
pytest -q -m "not live_model"
pytest -q -m "live_model"  # 仅有显式授权与专用测试配置时执行
```

另外应在 CI 里：

- 不注入真实付费模型 API Key 给普通单元测试。
- 在模拟环境中用 Fake Gateway 或 HTTP MockTransport 替换所有外部模型调用。
- 对意外实际外部网络请求采用显式失败保护。
- 将真实模型评测放在单独 Job，限制调用次数、预算和权限。
- 将生产 API Key 视为秘密，不能写进日志、测试样例或仓库。

测试替身能显著降低成本，但也可能掩盖真实 SDK 行为变化。因此仍应保留低频、受控的真实联通与回归验证。

## 20. 工程结论：用 Mock 测程序可靠性，用真实模型测模型能力

这一知识点的完整执行链为：

```text
定义模型接口
   ↓
注入可控模型替身
   ↓
预设正常输出或错误序列
   ↓
运行真实业务解析、校验、重试和工具执行代码
   ↓
断言状态、调用次数、工具边界和清理结果
   ↓
隔离执行真实供应商联通及模型效果评测
```

**最终需要形成的能力**并不是“会写一个 Mock 类”，而是能够把不同来源的故障转化为可复现、可定位、可回归的自动化测试，并准确知道测试到底验证了什么，没有验证什么。

## 22. 常见问题与容易混淆的结论

**Q：模拟模型返回 `{"answer": ...}` 就算测试通过了吗？**  
A：只有当真实的业务服务读取、校验、转换并产生符合预期的对外结果时，才算通过。直接断言 Fake 返回值没有价值。

**Q：Mock 的返回值固定，就能保证 CI 稳定吗？**  
A：不一定。真实异步超时、竞态条件、随机重试、共享状态或依赖版本仍可能导致不稳定。

**Q：暂时性错误一定应该重试吗？**  
A：不一定。还需要检查总耗时、并发预算、服务端重试建议、幂等性和用户是否取消。

**Q：为什么要保留真实模型评测？**  
A：Fake 只能验证程序如何处理预设结果，不能预测真正模型会输出什么、是否正确选工具或是否引用准确。

**Q：为什么最好在模型适配器边界 Mock，而不是将整个 Service Mock 掉？**  
A：因为学习目标就是验证 Service 对错误的处理；将 Service 也替换后，关键业务代码不再执行。

**Q：可以用 `AsyncMock` 模拟所有情况吗？**  
A：可以覆盖很多简单异步调用，但复杂多步工具调用和状态机通常更适合使用显式的 Fake，以便控制执行路径并保留中间状态。

## 附录 A：完整可运行的业务与模型替身代码（`llm_app.py`）

```python
"""Deterministic example: LLM gateway contract, validation, retry, tool execution."""
from __future__ import annotations

import asyncio
import json
from dataclasses import dataclass
from typing import Any, Literal, Protocol

from pydantic import BaseModel, ConfigDict, Field, ValidationError, model_validator


class TemporaryProviderError(Exception):
    """Retryable provider failure, e.g. transient 503."""


class PermanentProviderError(Exception):
    """Non-retryable provider error."""


class ToolExecutionError(Exception):
    """Expected error returned by a tool adapter."""


@dataclass(frozen=True)
class ToolCall:
    name: str
    arguments: dict[str, Any]


@dataclass(frozen=True)
class ModelReply:
    text: str | None = None
    tool_call: ToolCall | None = None
    refused: bool = False
    finish_reason: str = "stop"


class ModelGateway(Protocol):
    async def complete(self, prompt: str, tool_result: dict[str, Any] | None = None) -> ModelReply: ...


class ToolGateway(Protocol):
    async def lookup_rule(self, rule_id: str) -> dict[str, Any]: ...


class ToolArgs(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)
    rule_id: str = Field(min_length=1, max_length=64)


class AnswerPayload(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)
    status: Literal["answered", "needs_more_info"]
    answer: str | None
    citations: list[str]
    missing_fields: list[str]

    @model_validator(mode="after")
    def consistent(self) -> "AnswerPayload":
        if self.status == "answered" and (not self.answer or not self.citations):
            raise ValueError("answered result requires an answer and citations")
        if self.status == "needs_more_info" and not self.missing_fields:
            raise ValueError("needs_more_info requires missing_fields")
        return self


@dataclass(frozen=True)
class Outcome:
    status: str
    answer: AnswerPayload | None = None
    reason: str | None = None
    model_attempts: int = 0
    tool_calls: int = 0


@dataclass(frozen=True)
class CallFailure(Exception):
    kind: str
    attempts: int


class ChatService:
    def __init__(self, model: ModelGateway, tools: ToolGateway, *, timeout_seconds: float = 0.05,
                 max_attempts: int = 2, retry_delay: float = 0.0,
                 allowed_tools: frozenset[str] = frozenset({"lookup_rule"})):
        if timeout_seconds <= 0 or max_attempts < 1 or retry_delay < 0:
            raise ValueError("invalid call policy")
        self.model = model
        self.tools = tools
        self.timeout_seconds = timeout_seconds
        self.max_attempts = max_attempts
        self.retry_delay = retry_delay
        self.allowed_tools = allowed_tools

    async def _call(self, prompt: str, tool_result: dict[str, Any] | None = None) -> tuple[ModelReply, int]:
        for attempt in range(1, self.max_attempts + 1):
            try:
                reply = await asyncio.wait_for(
                    self.model.complete(prompt, tool_result),
                    timeout=self.timeout_seconds,
                )
                return reply, attempt
            except asyncio.CancelledError:
                raise  # external cancellation must propagate
            except (asyncio.TimeoutError, TemporaryProviderError) as exc:
                kind = "model_timeout" if isinstance(exc, asyncio.TimeoutError) else "provider_unavailable"
                if attempt == self.max_attempts:
                    raise CallFailure(kind, attempt) from exc
                if self.retry_delay:
                    await asyncio.sleep(self.retry_delay)
            except PermanentProviderError as exc:
                raise CallFailure("provider_rejected", attempt) from exc
        raise AssertionError("unreachable")

    async def ask(self, prompt: str) -> Outcome:
        total_attempts = 0
        tool_calls = 0
        try:
            reply, n = await self._call(prompt)
            total_attempts += n
            if reply.tool_call is not None:
                request = reply.tool_call
                if request.name not in self.allowed_tools or request.name != "lookup_rule":
                    return Outcome("invalid_tool", reason="unavailable tool", model_attempts=total_attempts)
                try:
                    args = ToolArgs.model_validate(request.arguments)
                except ValidationError:
                    return Outcome("invalid_tool_arguments", model_attempts=total_attempts)
                try:
                    result = await self.tools.lookup_rule(args.rule_id)
                    tool_calls += 1
                except ToolExecutionError:
                    tool_calls += 1
                    return Outcome("tool_error", model_attempts=total_attempts, tool_calls=tool_calls)
                # Real tool output is a data argument, not a system instruction.
                reply, n = await self._call(prompt, tool_result=result)
                total_attempts += n
                if reply.tool_call is not None:
                    return Outcome("tool_budget_exceeded", model_attempts=total_attempts, tool_calls=tool_calls)
            if reply.refused:
                return Outcome("model_refusal", model_attempts=total_attempts, tool_calls=tool_calls)
            if reply.finish_reason != "stop":
                return Outcome("incomplete_output", reason=reply.finish_reason,
                               model_attempts=total_attempts, tool_calls=tool_calls)
            if not reply.text:
                return Outcome("empty_output", model_attempts=total_attempts, tool_calls=tool_calls)
            try:
                decoded = json.loads(reply.text)
            except json.JSONDecodeError:
                return Outcome("invalid_json", model_attempts=total_attempts, tool_calls=tool_calls)
            try:
                answer = AnswerPayload.model_validate(decoded)
            except ValidationError as exc:
                missing = any(error["type"] == "missing" for error in exc.errors())
                return Outcome("missing_field" if missing else "invalid_schema",
                               model_attempts=total_attempts, tool_calls=tool_calls)
            return Outcome("needs_more_info" if answer.status == "needs_more_info" else "success",
                           answer=answer, model_attempts=total_attempts, tool_calls=tool_calls)
        except CallFailure as exc:
            return Outcome(exc.kind, model_attempts=total_attempts + exc.attempts,
                           tool_calls=tool_calls)


class ScriptedModel:
    """Sequential fake: every call consumes one scripted reply/error/function."""
    def __init__(self, *actions: ModelReply | Exception | Any):
        self._actions = list(actions)
        self.call_args: list[tuple[str, dict[str, Any] | None]] = []

    async def complete(self, prompt: str, tool_result: dict[str, Any] | None = None) -> ModelReply:
        self.call_args.append((prompt, tool_result))
        if not self._actions:
            raise AssertionError("script exhausted: unintended model invocation")
        action = self._actions.pop(0)
        if isinstance(action, Exception):
            raise action
        if callable(action):
            return await action(prompt, tool_result)
        return action


class FakeTools:
    def __init__(self, data: dict[str, dict[str, Any]] | None = None,
                 failure: Exception | None = None):
        self.data = data or {}
        self.failure = failure
        self.calls: list[str] = []

    async def lookup_rule(self, rule_id: str) -> dict[str, Any]:
        self.calls.append(rule_id)
        if self.failure is not None:
            raise self.failure
        if rule_id not in self.data:
            raise ToolExecutionError("rule not found")
        return self.data[rule_id]
```
