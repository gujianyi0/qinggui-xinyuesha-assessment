测试、部署与效果验证（三）：真实模型效果评测与模型替身程序测试的分离

对应学习目标：将模型效果测试与程序测试分开：真实模型验证回答与工具选择，模型替身验证错误处理和系统可靠性。

文档类型：独立技术知识手册；版本：1.0；编写日期：2026-11-12。示例采用 Python 3.13、pytest、Pydantic；真实模型调用为独立、显式启用的可选实验，不作为普通测试的前提。

1. 核心问题：为什么必须分离两类测试

一个 AI 应用往往同时包含概率性决策系统（大模型）与确定性的程序控制系统（参数校验、权限、数据库事务、重试、接口）。这两种系统采用同一套测试方法，会让测试结果失去明确含义。

  • 模型效果评测（Model Evaluation / Evals）：回答“真实模型在这类任务中是否理解问题、选择合适工具、根据证据答对、在信息不足时合理澄清”。对象是实际调用的模型与提示词、工具定义、上下文、检索结果等组合。
  • 程序测试（Software Tests）：回答“假设模型给出某个结果或者发生某类故障，我们编写的程序是否按照规定正确处理”。对象是应用自身代码，包括输入/输出校验、超时、取消、权限、异常传播、任务状态和数据库事务。

模型替身无法证明真实模型聪明，也不需要证明；真实模型偶尔答对，也不能证明程序能承受异常。 两套测试各自提供不重叠、又共同必要的证据。

1.1 一个对照案例

用户询问：“游戏版本 v1 中，角色 A 的生命值是多少？”应用有 lookup_rule(rule_id) 工具，权威规则写明生命值为 4。

测试问题 应使用什么 能证明什么
模型是否知道该查规则，而不是猜数值？ 真实模型 + 固定任务集 工具选择是否合适
模型是否把查询条件设置成正确版本？ 真实模型 + 工具轨迹评分 工具参数是否适合任务
获得真实规则后是否回答“4”？ 真实模型 + 独立规则答案 事实性和证据利用情况
工具返回 {"error":"NOT_FOUND"} 后接口是否正确处理？ 可控模型/工具替身 错误传播与业务状态
模型输出非法 JSON 后是否拒绝持久化？ 替身 + Pydantic + pytest 输出契约与失败分支
某个请求超时是否阻塞其他用户？ 延迟替身 + 并发测试 超时、取消、事件循环行为
同一反馈重复提交是否产生两条记录？ 替身 + 真实测试数据库 幂等与事务一致性

上述测试不能互相代替。一次完整的模型输出正确，完全可能与一个存在严重权限漏洞的后端共存。

2. 四个测试层次，而不是只分成两堆

实际应用可以用四层结构理解测试范围：

text
真实用户任务
  │
  ├── A. 模型能力评测（真实模型）
  │      任务 → 模型 → 回答/工具决策 → 独立评分
  │
  ├── B. Agent 流程评测（真实模型 + 受控工具环境）
  │      任务 → 模型决策 → 工具实际执行 → 回答 → 轨迹/最终结果评分
  │
  ├── C. 应用程序测试（脚本化模型替身）
  │      固定输出/故障 → API → 业务代码 → 数据库/状态验证
  │
  └── D. 真实基础设施集成测试
         API → PostgreSQL → Kafka/Worker → Redis → 故障恢复

A、B 属于模型效果相关验证；C 属于程序可靠性；D 属于系统集成可靠性。D 可以使用替身避免模型费用，但应接入真实的数据库、消息中间件等，以发现模拟器无法体现的真实语义。

对每次测试结果应准确标注范围：“模拟模型 + SQLite 通过”不等于“真实模型 + PostgreSQL + Kafka 通过”。

3. 可测试架构：把模型调用隔离在接口边界

核心方法是依赖倒置：业务服务依赖抽象模型接口，不依赖某家服务商 SDK 的具体网络请求。

python
from typing import Protocol

class ModelGateway(Protocol):
    async def generate(self, messages: list[dict]):
        ...

生产运行时，可以注入实际 API Adapter；测试运行时，注入 ScriptedGateway（预置响应队列）。这样业务代码只有一份，替换的是外部依赖，不是另一份简化实现。

text
                    ┌─────────真实模型 API─────────┐
FastAPI → AgentService → ModelGateway              │
                    └─────────脚本化模型替身────────┘
                         ↓
                   工具权限 / 数据校验
                         ↓
                   业务事务 / 运行状态

需要坚持两点：

  1. 替身只模拟被依赖的模型接口，不应重新实现整个业务规则；否则测试可能绕开实际的被测代码。
  2. 输出校验、工具白名单、授权和事务逻辑必须仍然运行真实程序代码；不能用一个固定的“成功返回值”把这些路径全部跳过。

4. 模型替身的四种主要类型

类型 定义 适用情况 注意事项
Stub 按预先设置返回固定输出 特定响应或错误分支 不检验复杂交互细节
Mock 记录调用，支持断言参数及调用次数 验证调用契约 不应使测试过度依赖内部实现细节
Fake 运行简化但功能完整的实现 例如内存知识库、任务存储 与真实基础设施语义可能不同
Spy 记录真实或委托执行过程 调用链核对与审计 注意保密和副作用

Python 中常见手段：unittest.mock.Mock、AsyncMock、side_effect、pytest.monkeypatch、FastAPI 的 dependency_overrides、HTTPX MockTransport。它们是工具，不是测试级别；测试级别由实际覆盖的组件决定。

4.1 脚本化替身（Scripted Model）的设计

一个良好的脚本化模型应能够：

  • 按顺序返回多个响应（先请求工具，再返回最终回答）。
  • 在指定步骤抛出临时或永久异常。
  • 模拟延迟，并在取消时留下可核验的取消记录。
  • 保留收到的消息，方便检查应用是否回传了真实工具结果。
  • 在脚本用尽时立即报错，避免使用隐式默认值掩盖调用失控。

本手册附录中的 ScriptedGateway 就实现了这些行为。

5. 程序测试应覆盖的故障矩阵

故障注入的目标是穷尽关键状态转移和异常处理分支，不是随机让模型输出奇怪文字。

编号 故障或正常路径 关键断言 层级
S01 正常 JSON 回答 返回已校验结构 单元/服务
S02 无法解析的 JSON 错误被分类，不能当作成功保存 单元/服务
S03 缺少必填字段 输出 Schema 检查失败 单元/服务
S04 字段类型错误 类型拒绝或明确转换规则 单元/服务
S05 多余的禁用字段 拒绝异常结构 单元/服务
S06 模型空响应 明确输出缺失 单元/服务
S07 模型明确拒答 与格式故障分开表示（业务实现可扩展） 服务
S08 信息不足 可澄清/弃答，不凭空生成 服务
S09 模型调用超时 任务取消、资源释放、正确错误状态 异步
S10 临时网络异常 有界重试，最终可成功 服务
S11 多次临时失败 重试耗尽，不能无限循环 服务

6. Mock 应断言哪些内容

一个错误的测试例子是：

python
# 这种测试只证明预设的返回值等于预设值。
mock_model.return_value = "4"
assert mock_model() == "4"

较有意义的测试是：

python
# 真实 AgentService 接收到模型工具调用后：
# 1. 校验工具参数；2. 查受控数据；
# 3. 将真实工具结果交还模型；4. 校验最终结构。
result = await service.run("查角色 A 的规则")
assert result.answer == "4"
assert "lookup_rule" in result.tools_executed
assert model.received[1][-1]["content"] == "角色A生命值为4"

对于接口，除了返回文本，还要检查 HTTP 状态、错误码、数据库副作用和授权边界。对于异步操作，还要验证取消是否传播、是否关闭客户端和连接、有没有遗留后台任务。

7. 真实模型评测必须具有独立参考答案

真实模型评测需要先构造 Gold Dataset（独立参考集），而不是让当前被测模型自己给自己出题、自己确定正确答案。

推荐的单条评测样例结构：

json
{
  "case_id": "rule-001",
  "question": "在规则版本 v1 中，角色 A 的基础生命值是多少？",
  "expected_facts": [{"field":"hp", "value":4}],
  "expected_tool": "lookup_rule",
  "expected_arguments": {"rule_id":"r1"},
  "supporting_sources": ["rule:v1:a"],
  "knowledge_snapshot": "kb-v1",
  "assessment_policy": "依据原始规则，回答数值及可核查来源"
}

样例的答案和来源应由可核查的原始规则、结构化业务数据或独立人工标注建立。知识库发生变更时，应冻结旧快照或显式产生新的评测版本，不能在比较前后两版时偷偷更换标准答案。

7.1 评测集包含哪些问题

一般至少包含：

  • 正常问题：答案可从固定来源直接验证。
  • 多步骤问题：需要先查结构化数据，再用规则解释。
  • 工具选择问题：需要调用某个工具，或者根本不应调用工具。
  • 工具参数问题：检查版本、ID、查询范围是否正确。
  • 无答案问题：资料确实不足，应澄清或弃答。
  • 冲突问题：多版本资料不一致，需要限定范围。
  • 安全边界问题：注入文本、越权要求、禁止写入。
  • 多轮问题：上一次的问题条件仍然生效。
  • 回归问题：历史上出现过的真实缺陷。

只收集“简单且有答案”的问题，会高估模型在真实业务中的可靠程度。实际生产中的分布、边界情况与高损失错误要单独覆盖。

8. 如何衡量“回答正确”

不能把一个单一分数当成所有质量指标。

8.1 有确定答案的任务

对于唯一数值、枚举、版本号、合法 ID 等任务，可以使用程序性评分，例如：

  • 精确匹配（Exact Match）：答案是否与标准值一致。
  • 类型和范围校验：结果是否符合业务定义。
  • 程序实际计算：金额、数量、比例等计算应由代码进行。
  • 数据库结果核对：生成内容是否与受控查询结果一致。

示例中，4 与 5 的不同应该被判错。不要让“回答很流畅”抵消关键事实错误。

8.2 开放式生成任务

对于解释、总结或多段论述，应拆分要点：覆盖必需事实、是否有无依据陈述、是否遵守约束、是否提供适当的不确定性说明。可以使用人工标注或经过校准的 LLM-as-a-Judge，但模型评分器本身可能偏向某种措辞、结构或答案长度。

8.3 证据与引用

区分以下层次：

  1. 引用格式正确：字段可解析。
  2. 引用 ID 存在：确实对应某份资料。
  3. 引用版本匹配：来源与问题版本一致。
  4. 引用能支持断言：原文在语义上确实证明这一说法。

自动比较 source_id 最多主要说明引用身份/版本对应情况；不能单凭 ID 匹配证明自然语言断言得到证据支持。若要评价第 4 层，需要规则化事实核验、人工审核或经人工校准的语义支持评分器。

9. 如何衡量“工具选择正确”

真实模型在 tool_choice="auto" 的条件下，可以自行选择是否使用工具。工具能力评测至少区分：

维度 观察对象 典型失误
是否调用工具 tool_calls 是否为空 需要查证时直接编造
工具名称 选择了哪个工具 应查规则却调用角色更新
工具参数 JSON 参数、版本、ID 传错 rule_id 或遗漏版本
调用顺序 前一步是否构成后一步前提 没获取资料就尝试总结
执行结果利用 是否使用工具真实返回的数据 查到 4 却回答 5
最终任务结果 是否完成用户要求 工具调用看似合理但任务失败

9.1 不要把正确工具路径定义得过死

有时同一任务可以通过 lookup_rule() 或 lookup_character() 两条路径正确完成，强制要求唯一工具会把合法行为判错。评测时可定义一组可接受路径，或者优先评价最终业务结果。

只有当工具选择本身是业务合规要求时，才应该强约束必须调用哪一个工具（例如余额必须从授权数据库读取，不能凭上下文推测）。

9.2 不要只看最后回答

如果模型先调用了危险工具，最后又生成一段看似正确的回复，不能判为完整成功。应该同时记录：

text
task_id / case_id
 ├─ 真实模型请求与版本
 ├─ 工具意图（工具名 + 参数）
 ├─ 程序参数校验与授权
 ├─ 工具执行真实结果
 ├─ 模型续接生成
 ├─ 最终回答与引用
 └─ 评分及错误归因

这里的轨迹是可观察执行行为，不是模型内部隐含推理的证明。

10. 如何组织真实模型端到端评测

对一个问题，严格的真实模型效果测试可以包括：

  1. 加载固定输入及知识库快照。
  2. 调用真实模型，并提供与生产一致的工具 Schema。
  3. 记录模型是否提出工具调用，以及工具名、参数和 call_id。
  4. 后端独立校验工具参数与权限；在只读且受控的测试环境执行。
  5. 将真实工具执行结果回传给模型，继续至完成或有界停止。
  6. 记录最终回答、引用、异常、工具轨迹、延迟、用量。
  7. 用事先冻结的正确答案/可接受路径评分。
  8. 输出逐条结果与整体统计，人工复核争议案例。

如果直接把正确答案放入系统提示词，测试会产生信息泄漏；如果在 Prompt 中强制调用指定工具，就不再是在测试自主工具选择。相同条件下比较工具选择效果时，通常应保持候选工具集、Schema 和资料快照一致。

字段 含义

12. 配对评测：修改模型或 Prompt 后怎样比较

设固定评测集包含同一批 case_id。将旧版系统视为 Baseline，新版系统视为 Candidate：

  • 对同一条案例分别记录回答、工具路径、引用、耗时和用量。
  • 先计算每条案例的得分，再算通过率；不能先汇总回答文字直接打一个“整体感觉分”。
  • 明确改进（旧失败、新通过）和回归（旧通过、新失败）。
  • 将高风险案例（错误权限、错误扣费、错误删除）单独设置上线门槛；平均分高不能抵消关键安全回归。
  • 对具有随机性的模型，采用重复运行估计稳定性，而不仅取一次随机输出。

例如，四条虚构样例出现以下配对结果：

案例 Baseline Candidate
A 通过 失败（回归）
B 通过 通过
C 失败 通过（改进）
D 失败 通过（改进）

Baseline 为 2/4，Candidate 为 3/4；虽然总体通过率从 50% 增至 75%，仍存在案例 A 的回归，需要分析其业务风险。

12.1 为什么需要重复实验

同样输入、同样提示词，模型也可能有不同输出。建议按业务场景重复运行，并报告每项任务的成功次数、失败次数与波动，而不是把一次 pass 当成稳定保证。

例如，某项任务 10 次只成功 7 次，代表在这 10 次观测中经验成功率是 70%；样本量有限，不能断言真实成功概率恰好是 70%。对关键操作，除了平均成功率，还应测试最坏情况、失败恢复及人工介入路径。

12.2 对比质量与资源消耗

可同时统计：

  • 回答正确率、引用支持率、工具调用正确率。
  • 业务任务成功率、无答案时的可靠弃答率。
  • 平均耗时、P50/P95 延迟。
  • 输入/输出 Token、API 费用、每个成功任务的成本。
  • 失败重试次数、工具调用次数、人工复核工作量。

若新版 Prompt 质量略好但成本翻倍，是否接受应由预先规定的业务阈值决定；不能只以模型回答看起来更长、更流畅判断收益。

13. 自动评分和 LLM-as-a-Judge 的边界

评分器一般有三类：

类型 适合检验 限制
确定性代码评分 固定答案、字段、工具 ID、参数、真实副作用 不容易理解自由文本的语义
模型评分器 解释完整度、语义支持、回答有用性 本身存在偏差、漂移和评分误差
人工评审 复杂业务情境、引用是否真正支持、争议案例 成本高、主观差异、速度慢

建议优先使用能被程序明确判断的指标；无法确定性评分的部分再引入 LLM-as-a-Judge，并使用人工标注集定期检验它的错误率和一致性。不要让评分模型直接读取 Baseline/Candidate 标签后再打分，避免版本名偏差。

14. CI 测试分层：避免日常提交触发付费 API

建议将测试划分为三条互不混淆的运行路径：

text
每次提交 / Pull Request
  ├─ pytest：逻辑、故障注入、模型替身（无 API 费用）
  ├─ FastAPI + 测试数据库集成测试（无需真实模型）
  └─ 静态检查、类型检查、依赖与安全检查

人工显式触发 / 受控周期性执行
  └─ 固定数据集 → 真实模型与工具 → 评测报告（可能付费）

发布前 / 重要架构变更
  └─ 真实 PostgreSQL/Kafka/Redis + 故障与恢复集成测试

“周期性”不等于无条件每天都跑付费模型。可以按成本预算、发布频率或实际需要选择触发规则。每个实际付费模型评测都应设置调用上限、成本上限、超时，以及日志脱敏。

14.1 CI 门槛的设计

程序层的关键不变量可以设置严格的必须通过条件：

  • 参数非法不能越权执行工具。
  • 未授权写入/删除不能发生。
  • 重复业务请求不得造成重复最终记录。
  • 超时后不得把不完整结果当作成功。

真实模型能力需要可解释的统计门槛：例如工具选择正确率、业务结果成功率不能低于基线；对于关键安全场景可以要求无错误或强制人工审批。门槛应基于实际数据量、业务风险与测量噪声设定，不应把少量样例上的偶然改进当成可靠结论。

15. 反模式与常见误判

  1. 用替身返回正确答案后宣称模型准确率 100%：只能证明模拟输入下的程序正确性。
  2. 用真实模型答对一次来证明程序可靠：没有覆盖异常和边界条件。
  3. 仅测试最终文本，不记录工具轨迹：可能隐藏错误工具调用和副作用。
  4. 让被测模型自己写标准答案：会引入循环验证和偏差。
  5. 只比较平均分：忽略单条高风险回归。
  6. 仅检查引用 ID 出现：不能证明引用内容支持陈述。
  7. 用工具强制选择测试模型自主工具选择：测试目标被改变。
  8. 让 Mock 重写业务逻辑：测试失去对真实代码的覆盖。
  9. 把模型失败一律标成超时：掩盖 JSON、权限、工具等不同故障。
  10. 把模拟 SQLite 事务测试称为 PostgreSQL 集成验证：不能推断真实数据库并发行为。
  11. CI 中默认调用付费接口：带来不可控成本、网络不稳定和隐私风险。
  12. 修改模型、提示词、工具描述与数据快照，却只记录模型版本：结果不可归因。

16.1 业务控制器包含的关键保证

  • 服务独立于具体模型提供商。
  • 模型调用具有单次超时、总超时与最大尝试次数。
  • 只允许执行已登记的只读工具。
  • 用 Pydantic 校验工具参数及最终 JSON 输出。
  • 将工具实际返回的数据交给模型续接，而不是预先写死最终回答。
  • 当模型轮次超限或输出不满足契约时明确报错。

16.2 评分器的设计

评分器独立于程序测试：

  • GoldCase 定义人工确认的参考答案和可接受的工具路径。
  • Observation 保存模型实际回答、工具调用、引用标识和用量。
  • grade() 分别计算回答、工具路径、参数、引用 ID 的正确情况。
  • paired_comparison() 强制比较两版相同的 case_id，输出改进和回归案例。

实现限制： 示例采用简单规范化后的精确字符串匹配，不具备完整语义判断能力；引用评分只检查已指定来源 ID 是否出现，不自动证明证据真实支持断言。这正是把独立语义评分器和人工核验单独保留的原因。

18. 真实模型评测与程序测试的结合方式

一种典型流程是：

阶段 A：替身保证程序可靠。运行快速、可重复的 pytest；非法 JSON、超时、工具失败、权限拒绝全部得到预期处理。

阶段 B：真实模型保证决策有效。使用固定的问题和独立资料验证答案、工具选择、参数和引用；找出模型产生的真实错误。

阶段 C：将真实失败转化为可复现测试。从真实评测的错误案例中提取非敏感、脱敏后的输出，加入替身测试验证程序是否正确处理；同时保留真实模型评测样例，防止模型侧回归。

阶段 D：部署集成保证跨组件可靠。使用 PostgreSQL、Kafka、Redis 的真实测试实例验证事务、消息重投、并发和故障恢复，而不是用一个内存 Fake 代替全部真实服务。

四个阶段的关系是互补，而不是先做一次之后就可以永久省略其中任意一项。

python
"""Offline-testable orchestration: model inference is injected, never hardwired."""
from __future__ import annotations
import asyncio
import json
from collections import deque
from dataclasses import dataclass, field
from typing import Any, Protocol
from pydantic import BaseModel, ConfigDict, Field, ValidationError


class TemporaryModelError(Exception):
    pass


class ModelCallFailed(Exception):
    pass


class InvalidModelOutput(Exception):
    pass


class ToolRejected(Exception):
    pass


class ToolFailed(Exception):
    pass


class TooManyModelTurns(Exception):
    pass


@dataclass(frozen=True)
class ModelTurn:
    content: str | None = None
    tool_name: str | None = None
    tool_args: dict[str, Any] | None = None


class ModelGateway(Protocol):
    async def generate(self, messages: list[dict[str, Any]]) -> ModelTurn: ...


@dataclass(frozen=True)
class ScriptStep:
    outcome: ModelTurn | Exception
    delay_seconds: float = 0.0


class ScriptedGateway:
    def __init__(self, steps: list[ScriptStep]):
        self.steps = deque(steps)
        self.call_count = 0
        self.received: list[list[dict[str, Any]]] = []
        self.cancel_count = 0

    async def generate(self, messages: list[dict[str, Any]]) -> ModelTurn:
        self.call_count += 1
        self.received.append([dict(item) for item in messages])
        if not self.steps:
            raise AssertionError("No scripted model step left")
        step = self.steps.popleft()
        try:
            if step.delay_seconds:
                await asyncio.sleep(step.delay_seconds)
        except asyncio.CancelledError:
            self.cancel_count += 1
            raise
        if isinstance(step.outcome, Exception):
            raise step.outcome
        return step.outcome


class Answer(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)
    answer: str = Field(min_length=1)
    source_id: str | None  # required, but nullable


class LookupArgs(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)
    rule_id: str = Field(min_length=1)


@dataclass(frozen=True)
class ServiceResult:
    answer: str
    source_id: str | None
    tools_executed: tuple[str, ...]


class AgentService:
    def __init__(
        self,
        gateway: ModelGateway,
        rules: dict[str, str],
        *,
        per_attempt_timeout: float = 0.1,
        total_timeout: float = 0.5,
        max_attempts: int = 2,
        max_model_turns: int = 3,
    ):
        self.gateway = gateway
        self.rules = rules
        self.per_attempt_timeout = per_attempt_timeout
        self.total_timeout = total_timeout
        self.max_attempts = max_attempts
        self.max_model_turns = max_model_turns

    async def _ask_model(self, messages: list[dict[str, Any]]) -> ModelTurn:
        for attempt in range(self.max_attempts):
            try:
                async with asyncio.timeout(self.per_attempt_timeout):
                    return await self.gateway.generate(messages)
            except (TimeoutError, TemporaryModelError) as exc:
                if attempt + 1 == self.max_attempts:
                    raise ModelCallFailed("Model unavailable after bounded retries") from exc
        raise AssertionError("unreachable")

    async def run(self, question: str) -> ServiceResult:
        messages: list[dict[str, Any]] = [{"role": "user", "content": question}]
        executed: list[str] = []
        async with asyncio.timeout(self.total_timeout):
            for _ in range(self.max_model_turns):
                turn = await self._ask_model(messages)
                if turn.tool_name is not None:
                    if turn.tool_name != "lookup_rule":
                        raise ToolRejected("Tool is not on the read-only allowlist")
                    try:
                        args = LookupArgs.model_validate(turn.tool_args)
                    except ValidationError as exc:
                        raise ToolRejected("Invalid tool arguments") from exc
                    try:
                        data = self.rules[args.rule_id]
                    except KeyError as exc:
                        raise ToolFailed("Rule not found") from exc
                    executed.append(turn.tool_name)
                    messages.append({"role": "assistant", "tool_call": {"name": turn.tool_name, "args": turn.tool_args}})
                    messages.append({"role": "tool", "name": turn.tool_name, "content": data})
                    continue
                if turn.content is None:
                    raise InvalidModelOutput("Missing final content")
                try:
                    raw = json.loads(turn.content)
                    answer = Answer.model_validate(raw)
                except (json.JSONDecodeError, ValidationError) as exc:
                    raise InvalidModelOutput("Invalid final answer") from exc
                return ServiceResult(answer=answer.answer, source_id=answer.source_id, tools_executed=tuple(executed))
            raise TooManyModelTurns("Agent exceeded configured model-turn limit")

"""Model-effect scoring: use ground truth created independently of the model."""
from __future__ import annotations
from dataclasses import dataclass
from typing import Any, Mapping


@dataclass(frozen=True)
class ToolCall:
    name: str
    arguments: Mapping[str, Any]


@dataclass(frozen=True)
class GoldCase:
    case_id: str
    question: str
    expected_answer: str
    accepted_tool_sequences: tuple[tuple[str, ...], ...]
    expected_args: Mapping[str, Any] | None
    supporting_source_ids: frozenset[str]


@dataclass(frozen=True)
class Observation:
    answer: str
    tool_calls: tuple[ToolCall, ...]
    cited_source_ids: frozenset[str]
    latency_ms: float = 0
    input_tokens: int | None = None
    output_tokens: int | None = None


@dataclass(frozen=True)
class Score:
    case_id: str
    answer_ok: bool
    tool_path_ok: bool
    arguments_ok: bool
    cited_ids_ok: bool

    @property
    def passed(self) -> bool:
        return self.answer_ok and self.tool_path_ok and self.arguments_ok and self.cited_ids_ok


def normalize(text: str) -> str:
    return " ".join(text.split()).casefold()


def grade(case: GoldCase, observation: Observation) -> Score:
    actual_names = tuple(c.name for c in observation.tool_calls)
    tool_ok = actual_names in case.accepted_tool_sequences
    if case.expected_args is None:
        args_ok = True
    else:
        args_ok = bool(observation.tool_calls) and dict(observation.tool_calls[0].arguments) == dict(case.expected_args)
    # An ID match proves only citation identity, not that its contents semantically entail a claim.
    citations_ok = case.supporting_source_ids.issubset(observation.cited_source_ids)
    return Score(
        case_id=case.case_id,
        answer_ok=normalize(case.expected_answer) == normalize(observation.answer),
        tool_path_ok=tool_ok,
        arguments_ok=args_ok,
        cited_ids_ok=citations_ok,
    )


def paired_comparison(cases: list[GoldCase], baseline: Mapping[str, Observation], candidate: Mapping[str, Observation]) -> dict[str, Any]:
    ids = {c.case_id for c in cases}
    if len(ids) != len(cases) or set(baseline) != ids or set(candidate) != ids:
        raise ValueError("Dataset and both result sets must have identical unique case IDs")
    before = {c.case_id: grade(c, baseline[c.case_id]) for c in cases}
    after = {c.case_id: grade(c, candidate[c.case_id]) for c in cases}
    improvements = sorted(i for i in ids if not before[i].passed and after[i].passed)
    regressions = sorted(i for i in ids if before[i].passed and not after[i].passed)
    n = len(ids)
    return {
        "baseline_passed": sum(s.passed for s in before.values()),
        "candidate_passed": sum(s.passed for s in after.values()),
        "baseline_rate": sum(s.passed for s in before.values()) / n if n else 0,
        "candidate_rate": sum(s.passed for s in after.values()) / n if n else 0,
        "improvements": improvements,
        "regressions": regressions,
    }

"""OPTIONAL paid live-model probe. Run only when explicitly chosen; not imported by pytest.

Usage:

    # supply these env variables via your own environment/secret manager
    # MODEL_API_KEY, MODEL_ID, MODEL_BASE_URL (if provider uses compatible API)

This script uses Chat Completions-compatible function tools. Adapt it if your provider

from __future__ import annotations
import asyncio
import json
import os
import time
from dataclasses import asdict, dataclass
from pathlib import Path
from typing import Any

from evaluate import GoldCase, Observation, ToolCall, grade

# An independent, frozen sample knowledge base, deliberately separate from the model.
RULES = {"r1": {"source_id": "rule:v1:a", "text": "在版本1中，角色A的基础生命值为4。"}}
CHARACTERS = {"a": {"source_id": "char:v1:a", "name": "角色A", "hp": 4}}

TOOLS = [
    {"type": "function", "function": {
        "name": "lookup_rule", "description": "按 rule_id 查询指定规则原文，不做写入。", 
        "parameters": {"type": "object", "properties": {"rule_id": {"type": "string"}},
                       "required": ["rule_id"], "additionalProperties": False},
    }},
    {"type": "function", "function": {
        "name": "lookup_character", "description": "按 character_id 查询游戏角色结构化属性，不做写入。",
        "parameters": {"type": "object", "properties": {"character_id": {"type": "string"}},
                       "required": ["character_id"], "additionalProperties": False},
    }},
]


def execute_readonly_tool(name: str, raw_arguments: str) -> dict[str, Any]:
    try:
        args = json.loads(raw_arguments)
        if not isinstance(args, dict):
            return {"error": "INVALID_ARGUMENTS"}
        if name == "lookup_rule" and set(args) == {"rule_id"} and isinstance(args["rule_id"], str):
            return RULES.get(args["rule_id"], {"error": "NOT_FOUND"})
        if name == "lookup_character" and set(args) == {"character_id"} and isinstance(args["character_id"], str):
            return CHARACTERS.get(args["character_id"], {"error": "NOT_FOUND"})
        return {"error": "TOOL_DENIED_OR_INVALID_ARGUMENTS"}
    except (ValueError, TypeError):
        return {"error": "INVALID_JSON_ARGUMENTS"}


async def observe_live(question: str) -> tuple[Observation, dict[str, Any]]:
    from openai import AsyncOpenAI  # delayed import, not required for offline tests

    key = os.environ["MODEL_API_KEY"]
    model = os.environ["MODEL_ID"]
    base_url = os.environ.get("MODEL_BASE_URL") or None
    client = AsyncOpenAI(api_key=key, base_url=base_url, timeout=30.0, max_retries=0)
    messages: list[dict[str, Any]] = [
        {"role": "system", "content": (
            "Answer the question using tools where necessary. Do not invent facts. "
            "The final assistant message must be a JSON object with fields "
            "answer (string) and citations (array of source_id strings). "
            "Missing evidence: answer '资料不足' and use no citations."
        )},
        {"role": "user", "content": question},
    ]
    tool_calls: list[ToolCall] = []
    raw_events: list[dict[str, Any]] = []
    input_tokens = 0
    output_tokens = 0
    answer = ""
    citations: frozenset[str] = frozenset()
    started = time.perf_counter()
    try:
        for step in range(3):
            result = await client.chat.completions.create(
                model=model, messages=messages, tools=TOOLS, tool_choice="auto",
            )
            if result.usage:
                input_tokens += result.usage.prompt_tokens
                output_tokens += result.usage.completion_tokens
            if not result.choices:
                raw_events.append({"error": "NO_CHOICES"})
                break
            message = result.choices[0].message
            tool_items = message.tool_calls or []
            raw_events.append({"turn": step, "finish_reason": result.choices[0].finish_reason,
                               "model": result.model, "tool_names": [x.function.name for x in tool_items]})
            if tool_items:
                messages.append({
                    "role": "assistant", "content": message.content,
                    "tool_calls": [{"id": x.id, "type": "function", "function": {
                        "name": x.function.name, "arguments": x.function.arguments}}
                        for x in tool_items],
                })
                for item in tool_items:
                    name, args_text = item.function.name, item.function.arguments
                    try:
                        args = json.loads(args_text)
                    except json.JSONDecodeError:
                        args = {}
                    tool_calls.append(ToolCall(name, args if isinstance(args, dict) else {}))
                    # Read-only local execution. All unrecognized tools are rejected.
                    observed = execute_readonly_tool(name, args_text)
                    raw_events.append({"tool": name, "result": observed})
                    messages.append({"role": "tool", "tool_call_id": item.id,
                                     "content": json.dumps(observed, ensure_ascii=False)})
                continue
            try:
                obj = json.loads(message.content or "")
                if isinstance(obj, dict) and isinstance(obj.get("answer"), str):
                    answer = obj["answer"]
                    ids = obj.get("citations", [])
                    if isinstance(ids, list) and all(isinstance(x, str) for x in ids):
                        citations = frozenset(ids)
                    else:
                        raw_events.append({"error": "INVALID_CITATION_IDS"})
                else:
                    raw_events.append({"error": "INVALID_FINAL_SHAPE"})
            except json.JSONDecodeError:
                raw_events.append({"error": "INVALID_FINAL_JSON"})
            break
        else:
            raw_events.append({"error": "MAX_MODEL_TURNS"})
    except Exception as exc:
        raw_events.append({"error": "MODEL_REQUEST_FAILED", "exception_type": type(exc).__name__})
    finally:
        await client.close()
    observation = Observation(answer, tuple(tool_calls), citations,
                              latency_ms=(time.perf_counter() - started) * 1000,
                              input_tokens=input_tokens, output_tokens=output_tokens)
    metadata = {"model_requested": model, "raw_events": raw_events}
    return observation, metadata


async def main() -> None:
    if not os.environ.get("MODEL_API_KEY") or not os.environ.get("MODEL_ID"):
        raise SystemExit("Set MODEL_API_KEY and MODEL_ID explicitly to opt into paid live evaluation")
    case = GoldCase("sample1", "查询规则 r1：角色A在版本1的基础生命值是多少？", "4",
                    (("lookup_rule",),), None,
                    frozenset({"rule:v1:a"}))
    observation, metadata = await observe_live(case.question)
    result = {"case_id": case.case_id, "score": asdict(grade(case, observation)),
              "observation": asdict(observation), "metadata": metadata}
    # Example data is synthetic, but real-world prompts/results need redaction before storage.
    Path("live_eval_result.json").write_text(json.dumps(result, ensure_ascii=False, indent=2, default=list), encoding="utf-8")
    print(json.dumps({"case_id": case.case_id, "passed": grade(case, observation).passed,
                      "latency_ms": round(observation.latency_ms, 1)}, ensure_ascii=False))


if __name__ == "__main__":
    asyncio.run(main())
